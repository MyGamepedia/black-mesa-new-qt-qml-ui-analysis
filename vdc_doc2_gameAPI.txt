==Campaigns System==
The '''BlackMesaEngine''' singleton type (see below) can provide array of '''CampaignEntry''' objects, the objects are used in the QML code to create campaigns lists, for the official game campaign (file '''blackmesa.json''') in the '''Campaign''' section, and for '''Steam Workshop''' maps (custom campaigns). When an array of '''CampaignEntry''' objects requested from QML via {{code|listCampaignEntries()}}, the UI reads all JSON files provided in '''campaigns''' folder and returns the array of '''CampaignEntry''' objects. The UI hardcodes {{code|isOfficial}} parameter value for all '''CampaignEntry''' objects, sets false for all the objects, except '''blackmesa.json''', the UI sets true for it, via ''campaigns/blackmesa.json'' string check. Other parameter in a '''CampaignEntry''' object are defined and set by the JSON file, this means any static parameter and value for it can be added and used in the QML code for custom logic (e.g. a chance to get different chapter thumbnail). The original Black Mesa QML code only uses only:
* '''title''' - name for the campaign, can be translated via '''#''' at the start of string.
* '''imageSource''' - image for the campaign thumbnail.
* '''chapters''' - array of plain data objects, contains chapters for the campaign.

The original JSON file from Black Mesa also provides following parameters, but they are never used in the QML code:
* '''author''' - author name.
* '''description''' - short description of the campaign.
* '''url ''' - author's resource link.

From the '''chapters''' array, the original Black Mesa QML code only uses:
* '''title''' - name for the chapter, can be translated via '''#''' at the start of string.
* '''imageSource''' - image for the thumbnail for the chapter.
* '''levelName''' - BSP map file name to use for chapter launch.

The '''description''' parameter is unused.

If the JSON file provided only one chapter, the UI skips the chapter carousel entirely and launches the single chapter on '''START GAME''' button, instead of showing the chapters list.

Following format used in the JSON file (can be used as a template):
<source lang=json>
{
    "title": "CampaignName",
    "imageSource": "image://game/campaigns/CampaignName/images/CampaignLogo.jpg",
    "chapters": [
        {
            "title": "CampaignChapter1",
            "imageSource": "image://game/campaigns/CampaignName/images/CampaignChapter1.png",
            "levelName": "map1"
        },
        {
            "title": "CampaignChapter2",
            "imageSource": "image://game/campaigns/CampaignName/images/CampaignChapter2.png",
            "levelName": "map2"
        },
        {
            "title": "CampaignChapterX",
            "imageSource": "image://game/campaigns/CampaignName/images/CampaignChapterX.png",
            "levelName": "mapX"
        }
    ]
}
</source>

Adding a new JSON file in the folder will be enough for the UI to load show a custom campaign in the '''Steam Workshop''' section, note that it is recommended to keep images everything in '''campaigns''' folder, the ''ui/campaign/images/'' folder is designed for official campaigns. For custom official campaign in the '''Campaign''' section for a total convention (modification), just edit '''blackmesa.json''' file.

==VFS Protocol (vfs://)==
'''vfs://''' is a custom URL scheme registered into Qt's networking stack. It lets QML code load files through the {{source|4}} Engine's Virtual File System — meaning files can be resolved from [[VPK]] archives, mounted game directories, or any other path the engine has mounted, rather than the raw OS file system.

It is implemented as a custom '''QNetworkAccessManager''' (or equivalent network handler) that intercepts '''vfs://''' URLs and routes them through the Source Engine's '''IFileSystem''' interface. This is described in the Engine Integration Layer as the "Custom Network Access Manager" integration point. 

===URL Format===
<source lang=qml>
vfs:///path/to/file
</source>

The path is relative to the engine's search paths (same resolution rules as {{code|filesystem->Open()}}). The triple slash (///) is standard for a local-path URI with an empty host.

===How it's used in QML===
====Loading fonts via FontLoader====
'''theme.qml''' uses '''vfs:///''' to load all UI fonts from the engine file system:

<source lang=qml>
FontLoader { source: "vfs:///ui/fonts/firamono-regular.ttf" }  
FontLoader { source: "vfs:///ui/fonts/notosans-light.ttf" }
</source>

Example can be found in '''theme.qml''' around lines 84-104.

====Reading config files via XMLHttpRequest====

'''input-bindings-manager.qml''' uses '''vfs:///''' to read '''config.cfg''' through an '''XMLHttpRequest'''-based helper:

<source lang=qml>
_readConfigFile("vfs:///cfg/config_example.cfg", function (response) { ... })
</source>

Example can be found in '''input-bindings-manager.qml''' around lines 247-249.

==image:// Image Provider==
'''image://''' is a QML built-in URL scheme for loading images through a custom image provider — a C++ class (QQuickImageProvider) registered into the QQmlEngine. The format is:

<source lang=qml>
image://<provider-id>/<path>  
</source>

In Black Mesa, the provider ID is game, so all image URLs start with '''image://game/'''. It is registered by BlackMesaUI.dll and handles both VTF and standard image formats, PNG normally, resolving paths through the Source Engine VFS.

The '''image://game/''' provider is the only way to load a VTF file in QML, the standard schemes do not know how to decode VTF.

===How to use it===

Assign the URL to the source property of a QML Image element:

<source lang=qml>
Image {  
    source: "image://game/ui/images/nav-logo.png"  
}
</source>

Example can be found in '''component-header.qml''' around lines 159-167.

===URL format===
<source lang=qml>
image://game/<vfs-path>  
</source>

The path after '''image://game/''' is the same VFS path that would be passed to the Source Engine file system - it can point inside VPK archives, game directories, etc.

===All usage patterns in the codebase===

Static PNG UI images:
<source lang=qml>
Image { source: "image://game/ui/images/unavailable.png" }
</source>

Example can be found in '''routeview-unavailable.qml''' around lines 5-12.


VTF background textures (wallpaper):
<source lang=qml>
background01: "image://game/materials/console/background01.vtf"
</source>

Example can be found in '''component-wallpaper.qml''' around lines 21-25.


Dynamic path construction (map thumbnails):
<source lang=qml>
source: [  
    "image://game/materials/vgui/multiplayer/map_backgrounds/",  
    model.value,  
    "_0_widescreen.vtf"  
].join('')
</source>

Example can be found in '''component-optionslist-input-map.qml''' around lines 86-95.


State-based image switching (hover effect):
<source lang=qml>
source: discordLinkArea.containsMouse  
    ? "image://game/ui/images/discord-purple.png"  
    : "image://game/ui/images/discord-white.png"
</source>

Example can be found in '''component-footer.qml''' around lines 143-144.


Asynchronous loading (for heavy textures, avoids blocking the UI thread):
<source lang=qml>
Image {  
    source: "image://game/materials/vgui/multiplayer/map_backgrounds/"+map+"_0_widescreen_16_10.vtf"  
    asynchronous: true  
}
</source>


Example can be found in '''routeview-join.qml''' around lines 249-257.


Path stored in a data model (save game thumbnail):
<source lang=qml>
thumbnailUrl: "image://game/ui/images/newSaveThumbnail.png"
</source>

Example can be found in '''routeview-savegame.qml''' at line 55.

==BlackMesaEngine QML Type==
Provides access to the underlying Black Mesa engine interface, enabling communication between the QML UI and the game engine.

Import Statement: {{code|import CrowbarCollective 1.0}}. Singleton instance: {{code|BlackMesaEngine}}.

===Detailed Description===
'''BlackMesaEngine''' is a singleton type exposed to the QML environment that provides a public set of functions for interacting with the Source engine running Black Mesa. It allows modders and UI developers to execute engine commands, retrieve game state, interact with [[Steam]], manage saves, manipulate [[ConVar|console variables]] (ConVars or Cvar for short), query input bindings, and receive engine/UI signals without needing to write C++ code.

Because it is registered as a singleton, there is no need to instantiate it. Simply use {{code|BlackMesaEngine.<methodName>()}} after importing the module.

Code example:
<source lang=qml>
import CrowbarCollective 1.0

Component.onCompleted: {
    console.log(BlackMesaEngine.getLevelName())
}
</source>

===Enumerations===
====KeyCode====
Defines the numeric codes for keyboard keys, mouse buttons, generic joysticks, XBox 360 controllers, and Steam controllers. Used for input binding and key capturing.

The full list is large and maps to the engine button code table. For UI code, prefer converting between key names and key codes with {{code|keyButtonStringToCode()}} and {{code|keyButtonCodeToString()}}.

Example names include '''KEY_ESCAPE''', '''KEY_ENTER''', '''KEY_SPACE''', '''KEY_UP''', '''KEY_DOWN''', '''MOUSE_LEFT''', '''MOUSE_RIGHT''', and '''KEY_XBUTTON_A'''.

===Signals===
*{{code|levelLoadingStarted(string levelName, bool isBackgroundLevel, bool showProgressDialog)}} - emitted when map loading begins.
*{{code|levelLoadingFinished(bool isError, string failureReason, string extendedReason)}} - emitted when a map has finished loading or failed.
*{{code|disconnectedFromServer()}} - emitted when the client drops connection to the server.

*{{code|gameUIActived()}} - emitted when the game UI gains focus. The spelling is intentional and matches the exposed API.
*{{code|gameUIHidden()}} - emitted when the game UI loses focus and closes.
*{{code|keyCaptured(int keyButtonCode)}} - emitted after '''requestKeyCapture()''' is called and the user presses a key. '''keyButtonCode''' corresponds to the '''KeyCode''' enum.
*{{code|gameConsoleActived()}} - emitted when the developer console opens. The spelling is intentional and matches the exposed API.
*{{code|gameConsoleHidden()}} - emitted when the developer console closes.
*{{code|gameConsoleCleared()}} - emitted when the developer console output is cleared.
*{{code|gameConsoleMessagesReceived(list messagesList)}} - emitted periodically with a queue of console logs. Each object contains color and text.
*{{code|matchmakingServerResponded(var serverEntry, string queryHandle)}} - emitted when a server responds during a matchmaking query.
*{{code|matchmakingQueryCompleted(string queryHandle)}} - emitted when a matchmaking query finishes scanning.
*{{code|navigationSourceChanged(int navigationSourceType)}} - emitted when the input device changes. Known values are 0 for keyboard/mouse, 1 for controller, and 2 for '''Steam''' controller.
