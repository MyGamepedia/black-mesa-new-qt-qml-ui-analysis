===devtest.qml===  
  
{{code|devtest.qml}} is a standalone developer test harness. It is '''not registered''' in {{code|qmldir}}, is '''not referenced''' anywhere in the codebase, and has no corresponding entry in {{code|routes.qml}}. It cannot be loaded through any normal UI flow and exists solely as an offline development tool for exercising engine API calls.  
  
The root element is a {{code|FocusScope}} (id: {{code|rootItem}}) with a fixed size of 1600×900. It does not use {{code|Theme}}, {{code|L10n}}, {{code|Sound}}, or any other singleton from the production UI.

====Deferred Startup Timer — {{code|deferredCompletedTimer}}====  
  
A {{code|Timer}} with {{code|interval: 1250}}, {{code|repeat: false}}, and {{code|running: true}}. It fires automatically 1250 ms after construction and performs three engine calls:  
  
# <code><nowiki>BlackMesaEngine.listSaveEntries()</nowiki></code> — result is JSON-logged and assigned to {{code|listSaveEntriesGrid.model}}.  
# <code><nowiki>BlackMesaEngine.requestInternetServerList()</nowiki></code> — handle is stored in {{code|d.queryHandle}}.  
# <code><nowiki>BlackMesaEngine.listAchievementEntries()</nowiki></code> — result is JSON-logged to the console only; not displayed in the UI.  
  
====Server Response Handler — {{code|Connections}}====  
  
Listens to {{code|BlackMesaEngine.onMatchmakingServerResponded}}. On each response:  
  
# Logs {{code|queryHandle}}, {{code|serverEntry.steamApplicationId}}, and <code><nowiki>BlackMesaEngine.getSteamApplicationId()</nowiki></code> to the console.  
# Filters the entry: only appends to {{code|serverEntriesList.model}} if <code><nowiki>serverEntry.steamApplicationId === BlackMesaEngine.getSteamApplicationId()</nowiki></code> '''and''' <code><nowiki>serverEntry.gameDirectory === "bms"</nowiki></code>.  
  
Two alternative filter conditions are present as comments: one for CS:GO (app ID 730, directory {{code|csgo}}) and one for Black Mesa (app ID 362890). The comment notes that the CS:GO filter was used because the Black Mesa server list was empty at the time of writing.

====Notable Issues====  
  
1. '''{{code|queryHandle}} is referenced unqualified in the {{code|Connections}} block.''' Line 69 logs {{code|queryHandle}} directly. In QML scope resolution, this does not resolve to {{code|d.queryHandle}} — {{code|queryHandle}} is a property of the {{code|d}} object, not of {{code|rootItem}} or any enclosing scope. The value logged will be {{code|undefined}}. The correct reference is {{code|d.queryHandle}}.  
  
2. '''{{code|QtGraphicalEffects 1.0}} is imported but unused.''' No graphical effect type is instantiated anywhere in the file.  
  
3. '''{{code|QtQuick.Layouts 1.2}} differs from the rest of the codebase.''' All production files use {{code|QtQuick.Layouts 1.1}}. This is a minor inconsistency with no functional impact.  
  
4. '''Fixed 1600×900 size with no {{code|Theme}} scaling.''' The root item is hardcoded to 1600×900 and no {{code|Theme.widthScale}} or {{code|Theme.heightScale}} is applied to any dimension. The file is not intended for production display.  
  
5. '''Native Qt {{code|Button}} elements instead of custom button components.''' The production UI uses {{code|CTAButton}}, {{code|DefaultButton}}, etc. This file uses the unstyled {{code|QtQuick.Controls 2.2}} {{code|Button}} directly.  
  
6. '''{{code|listAchievementEntries()}} output is console-only.''' The achievement data is fetched and logged but never displayed in the UI, unlike the save entries and server entries which have dedicated visual sections.  
  
7. '''The {{code|Rectangle}} border overlay inside {{code|RowLayout}} uses {{code|anchors.fill: parent}}.''' The {{code|RowLayout}} is not an {{code|Item}} subtype that supports {{code|anchors.fill}} children in the same way as a plain {{code|Item}}. The border rectangle will fill the layout but may not clip correctly against the button children.

===input-bindings-manager.qml===  
  
{{code|input-bindings-manager.qml}} is registered in {{code|qmldir}} as {{code|singleton InputBindingsManager 1.0}}. It is the central state manager for the key bindings system, responsible for:  
  
* Translating between Qt key/mouse enum values and Source engine key name strings.  
* Mapping engine command strings to localized human-readable labels.  
* Loading and reverse-indexing the current bindings from {{code|config.cfg}}.  
* Managing the key-capture lifecycle (selection → capture → conflict resolution → write).  
* Emitting signals that cause binding display components to refresh.  
  
It is a {{code|pragma Singleton}} {{code|QtObject}} with 374 lines.

====Functions====  
  
=====Private helpers=====  
  
{{code|_readConfigFile(url, callback)}} — Opens a VFS file via {{code|XMLHttpRequest}}, splits the response on newlines, and matches each line against the regex <code><nowiki>/bind\s+"(.*)"\s+"(.*)"/</nowiki></code>. Builds a command → key array map and passes it to {{code|callback}}. Used to read both {{code|vfs:///cfg/config.cfg}} and {{code|vfs:///cfg/config_default.cfg}}.  
  
{{code|_saveBindingModifications()}} — Executes <code><nowiki>exec userconfig.cfg; host_writeconfig</nowiki></code> via {{code|BlackMesaEngine.executeClientCommandUnrestricted()}} to persist all in-memory binding changes to disk.  
  
{{code|_resetConflicts()}} — Sets both {{code|conflicts}} and {{code|conflictCfg}} to {{code|null}}.  
  
=====Public API=====  
  
{{code|getBindingComponentConfig(command)}} — Returns a plain object <code><nowiki>{label, type: 'binding', command, key1: '', key2: ''}</nowiki></code> for initializing a binding row in a {{code|ListModel}}.  
  
{{code|getBindings(commands, callback)}} — Reads {{code|config.cfg}}, populates {{code|bindings}} and {{code|bindingsKeyMap}}, then calls {{code|callback}} with a filtered map containing only the entries whose command strings appear in the {{code|commands}} array. Called by {{code|component-binding.qml}} on load and after every {{code|bindingSet}}/{{code|bindingClear}}/{{code|defaultsRestored}} signal.  
  
{{code|selectBinding(cfg)}} — Sets {{code|selectedCfg}} to {{code|cfg}}, making {{code|isSelected}} true. Called by {{code|component-optionslist-input-binding.qml}} when the user first clicks a {{code|BindingCell}}.  
  
{{code|clearSelection()}} — Sets {{code|selectedCfg}} to {{code|null}}.  
  
{{code|handleBindingResponse(event)}} — Invokes {{code|inputBindingCallback(event)}} and immediately sets {{code|inputBindingCallback}} to {{code|null}}, ending the capture session. Called by {{code|main.qml}} from three sources: {{code|onKeyCaptured}} (keyboard), a full-screen {{code|MouseArea}} {{code|onClicked}} (mouse buttons), and the same {{code|MouseArea}} {{code|onWheel}} (scroll wheel).  
  
{{code|startBindingRequest()}} — Begins the key capture sequence:  
# Snapshots {{code|selectedCfg}} into a local {{code|cfg}} variable.  
# Calls {{code|clearSelection()}} (sets {{code|isSelected}} to false).  
# Calls {{code|cfg.begin()}} to put the {{code|BindingCell}} into the {{code|"binding"}} visual state.  
# Calls {{code|BlackMesaEngine.requestKeyCapture()}} to tell the engine to route the next key event to the UI.  
# Sets {{code|inputBindingCallback}} to a closure that handles the captured event (see below).  
  
{{code|clearSelectedBinding()}} — Unbinds the key at {{code|selectedCfg[selectedCfg.ordinal]}} via {{code|BlackMesaEngine.executeClientCommandUnrestricted('unbind ...')}}, saves, and emits {{code|bindingClear()}}.  
  
{{code|restoreDefaultBindings()}} — Reads {{code|config_default.cfg}} via XHR (result is discarded), then executes {{code|unbindall}} and {{code|exec config_default.cfg}}, saves, and emits {{code|defaultsRestored()}}.  
  
====Key capture lifecycle====  
  
The full flow from user interaction to engine write:  
  
# User clicks a {{code|BindingCell}} (first click) → {{code|component-optionslist-input-binding.qml}} calls {{code|InputBindingsManager.selectBinding(cfg)}} → {{code|isSelected}} becomes {{code|true}}.  
# User clicks the same cell again (second click) → {{code|BindingCell.startBinding()}} calls {{code|InputBindingsManager.startBindingRequest()}} → {{code|isBinding}} becomes {{code|true}}.  
# {{code|main.qml}} activates a full-screen {{code|MouseArea}} at {{code|z: 2000}} (enabled only while {{code|isBinding}} is {{code|true}}) to intercept mouse input.  
# The engine fires {{code|onKeyCaptured}} (keyboard) or the {{code|MouseArea}} fires {{code|onClicked}}/{{code|onWheel}} → {{code|handleBindingResponse(event)}} is called.  
# Inside {{code|inputBindingCallback}}:  
#* If {{code|event.key [[=]] 'ESCAPE'}}: calls {{code|cancel()}}, which calls {{code|cfg.end()}} with the original key and resets conflicts. No binding change occurs.  
#* If the pressed key is already bound to a ''different'' command: sets {{code|conflicts}} and {{code|conflictCfg}}. The UI ({{code|routeview-bindings.qml}}) shows a conflict alert with Confirm/Cancel buttons. {{code|conflictCfg.confirm}} and {{code|conflictCfg.cancel}} are the resolution callbacks.  
#* Otherwise: calls the inner {{code|setBinding()}} helper, which executes {{code|unbind}} on the old key and {{code|bind KEY "COMMAND"}} for each of {{code|key1}} and {{code|key2}}, then saves and emits {{code|bindingSet()}}.  
  
====Notable Issues====  
  
1. '''{{code|bindingsKeyMap.push(command)}} is a bug.''' In {{code|getBindings()}}, when a key is already present in {{code|bindingsKeyMap}}, the code calls {{code|bindingsKeyMap.push(command)}} instead of {{code|bindingsKeyMap[key].push(command)}}. {{code|bindingsKeyMap}} is a plain object, not an array, so {{code|push}} is {{code|undefined}} and this call throws a TypeError. The second command for any multiply-bound key is never added to the reverse map, meaning conflicts involving keys bound to more than one command are silently missed.  
  
2. '''{{code|restoreDefaultBindings}} reads {{code|config_default.cfg}} but discards the result.''' The XHR parse is entirely redundant. The function executes {{code|unbindall; exec config_default.cfg}} unconditionally regardless of the parsed content. The commented-out block that would have used the parsed data was never re-enabled.  
  
3. '''{{code|isBinding}} and {{code|isSelected}} are writable.''' Both are declared as {{code|property bool}} rather than {{code|readonly property bool}}. External code can overwrite them, breaking the invariant that they reflect {{code|!!inputBindingCallback}} and {{code|!!selectedCfg}} respectively.  
  
4. '''{{code|Qt.Return}} instead of {{code|Qt.Key_Return}}.''' The Enter key entry in {{code|keyMap}} uses {{code|Qt.Return}} while every other entry uses the {{code|Qt.Key_*}} form. {{code|Qt.Return}} is a valid alias in Qt 5 but is inconsistent with the rest of the map.  
  
5. '''{{code|onKeyCaptured}} escape-to-deselect branch references undefined {{code|event}}.''' In {{code|main.qml}}, the {{code|onKeyCaptured}} handler contains an {{code|else if}} branch that checks <code><nowiki>InputBindingsManager.isSelected && event.key === Qt.Key_Escape</nowiki></code>. The {{code|onKeyCaptured}} signal provides {{code|keyButtonCode}}, not {{code|event}}. The {{code|event}} identifier is undefined in this scope, so the condition always evaluates to {{code|false}} (or throws a TypeError). Pressing Escape while a cell is selected but not in capture mode does not clear the selection via this path.  
  
6. '''{{code|keyMap}} does not cover numpad keys.''' The Source engine supports {{code|KP_INS}}, {{code|KP_END}}, {{code|KP_UPARROW}}, etc. None of the {{code|Qt.Key_0}}–{{code|Qt.Key_9}} entries distinguish between the main row and the numpad ({{code|Qt.KeypadModifier}} is not checked), and no {{code|Qt.Key_*}} numpad-specific constants are mapped.

===l10n.qml===  
  
{{code|l10n.qml}} is the '''central localization singleton''' for the entire UI. It is registered in {{code|qmldir}} as {{code|singleton L10n 1.0 l10n.qml}} and imported implicitly by every QML file in the module. Its sole purpose is to expose all UI-facing strings as a single frozen JavaScript object tree, fetched from the engine's localization system at construction time.  
  
The file is 410 lines and is a {{code|pragma Singleton}} {{code|QtObject}}.  
  
====Properties====  
  
{| class="standard-table"  
! Property  
! Type  
! Description  
|-  
| {{code|strings}}  
| {{code|variant}}  
| The full string map. Initialized by calling {{code|_getStringMap()}} at construction time. Not {{code|readonly}} — it can be reassigned from outside the singleton (see Notable Issues).  
|}  
  
====Functions====  
  
=====getString(key)=====  
  
A thin public wrapper around <code><nowiki>BlackMesaEngine.getLocalizedString(key)</nowiki></code>. Returns the localized string for the given engine localization key. Used internally by {{code|_getStringMap()}} to populate every entry in the string map, and also called directly by a small number of files (see Notable Issues).  
  
=====refreshStrings()=====  
  
Reassigns {{code|strings}} by calling {{code|_getStringMap()}} again. Intended to be called after a language change to rebuild the string map with the new locale. However, {{code|refreshStrings()}} is '''never called from any other QML file''' in the codebase — it is defined but has no callers. Language changes at runtime therefore cannot update the UI without a full restart.  
  
=====_getStringMap()=====  
  
Private function. Builds and returns the complete string map as a deeply frozen JavaScript object ({{code|Object.freeze()}} applied at every level). Called once at construction time and again if {{code|refreshStrings()}} is ever invoked. All string values are fetched via {{code|getString()}} at the moment of the call; the map is a snapshot, not a live binding.

====Usage across the codebase====  
  
{{code|L10n.strings.*}} is the standard access pattern and is used by 22 QML files. The four files that call {{code|L10n.getString()}} directly — {{code|component-optionslist-input-select.qml}}, {{code|component-optionslist-row.qml}}, {{code|routeview-game.qml}}, and {{code|utils.qml}} — bypass the frozen map and always fetch a live value from the engine, meaning those strings would update immediately if {{code|refreshStrings()}} were ever called, while all other strings would not.  
  
====Notable Issues====  
  
1. '''{{code|refreshStrings()}} is never called.''' The function is defined but has no callers in the codebase. A language change at runtime cannot update any {{code|L10n.strings.*}} binding without a full UI reload.  
  
2. '''{{code|strings}} is not {{code|readonly}}.''' The property is declared as {{code|property variant strings}}, not {{code|readonly property variant strings}}. Any component can reassign the entire string map from outside the singleton, bypassing {{code|Object.freeze()}}.  
  
3. '''{{code|video_desc_usage_ram}} key name is misleading.''' The property is named {{code|ram}} but its localization key is {{code|#QTUI_Option_Video_Desc_Usage_VRAM}}. The label describes VRAM (video memory), not system RAM.  
  
4. '''{{code|menus.addons}} is never used.''' {{code|component-header.qml}} uses {{code|L10n.strings.menus.installed}} ({{code|#QTUI_Menu_Workshop_Installed}}) for the Workshop Addons tab label, not {{code|menus.addons}} ({{code|#QTUI_Menu_Workshop_Addons}}). The {{code|addons}} key is defined but has no callers.  
  
5. '''{{code|menus.campaigns}} references an unreachable route.''' {{code|routeview-campaigns.qml}} is an unregistered stub with no entry in {{code|routes.qml}}. The {{code|menus.campaigns}} string is defined but cannot be displayed through any normal navigation flow.  
  
6. '''Trailing comma in {{code|navigation}} sub-object.''' The last entry ({{code|change_tabs}}) is followed by a trailing comma. This is valid in ES5+ JavaScript but is inconsistent with all other sub-objects in the file, which do not have trailing commas.  
  
7. '''{{code|options.labels}} mixes two localization key namespaces.''' Most keys use {{code|#QTUI_*}} keys, but {{code|game_multiplayermodel}} uses {{code|#GameUI_CharacterModel}} and {{code|game_multiplayerskin}} uses {{code|#GameUI_CharacterSkin}} — legacy {{code|GameUI}} keys from the Source engine's original localization system, inconsistent with the rest of the file.

===main.qml===  
  
{{code|main.qml}} is the '''root QML document''' of the Black Mesa menu UI. It is the top-level {{code|Item}} instantiated by the engine and acts as the orchestration layer: it owns all global state, wires the engine's C++ signals to the QML layer, and composes the three primary visual regions ({{code|Header}}, {{code|Router}}, {{code|Footer}}) into a single full-screen layout.  
  
It is not registered in {{code|qmldir}} and is not a named component — it is loaded directly by the engine as the entry point.

====Theme Scaling Bindings====  
  
Two {{code|Binding}} elements keep {{code|Theme.widthScale}} and {{code|Theme.heightScale}} in sync with the window dimensions at all times:  
  
* <code><nowiki>Theme.widthScale = appRoot.width / 1920</nowiki></code>  
* <code><nowiki>Theme.heightScale = appRoot.height / 1080</nowiki></code>  
  
{{code|onWidthChanged}} and {{code|onHeightChanged}} additionally write {{code|Theme.rootWidth}} and {{code|Theme.rootHeight}} (which cannot be driven by {{code|Binding}} because they are plain writable properties, not bindable targets in the same way) and call {{code|wallpaper.updateBackgroundImage()}} to re-evaluate the widescreen threshold.  
  
====Focus, Visibility, and Key Handling====  
  
{{code|appRoot}} holds {{code|focus: true}} so it is the root of the keyboard focus chain. {{code|Keys.onPressed}} delegates all key events to {{code|BlackMesaUtils.navigationUIHandle(event)}} unless {{code|BlackMesaUtils.disableUINavigation}} is {{code|true}} (set by {{code|InputBindingsManager}} during key capture).  
  
{{code|onVisibleChanged}} calls {{code|BlackMesaEngine.setRootPanelVisibility(visible)}} to notify the engine whenever the root panel is shown or hidden.  
  
====Opacity Animation====  
  
A {{code|Behavior on opacity}} wraps the root fade in a {{code|SequentialAnimation}}:  
  
# Sets {{code|isMenuBlocked [[=]] true}} (disabling engine signal processing).  
# Runs a 625 ms {{code|NumberAnimation}} on {{code|appRoot.opacity}}.  
# Sets {{code|isMenuBlocked [[=]] false}}.  
  
The behavior is {{code|enabled: !didLoadLevel && !appRoot.isSaving}}, so it is bypassed when the UI is hiding due to a completed level load (instant cut) or a save operation (instant hide for screenshot).

=====Wallpaper=====  
  
A {{code|Wallpaper}} ({{code|component-wallpaper.qml}}) fills the entire {{code|appRoot}} behind the layout. It is not part of the {{code|GridLayout}}. Key bindings:  
  
* <code><nowiki>showSkrim: isInGame || router.currentRoute !== Routes.index</nowiki></code> — applies a dark overlay whenever the player is in-game or on any route other than the main index.  
* <code><nowiki>darkenSkrim: isInGame</nowiki></code> — uses the darker skrim opacity ({{code|Theme.opacity.pageSkrimDark}}) when in-game.  
* <code><nowiki>suppressAnimations: isLoadingLevel</nowiki></code> — disables crossfade animations during level loads to reduce GPU load.  
  
{{code|Wallpaper}} internally maintains a map of 19 background image keys ({{code|background01}}–{{code|background19}}) to {{code|.vtf}} file paths, with separate widescreen variants. The widescreen path is chosen when <code><nowiki>appRoot.width / appRoot.height >= 1.586</nowiki></code>. It also renders a bottom-right Black Mesa logo watermark, a left-edge gradient using {{code|Theme.colors.highlight}}, and a secondary gradient using {{code|Theme.colors.subNavBackground}}, all of which fade in/out via {{code|showExtras}}.  
  
=====Header=====  
  
The {{code|Header}} ({{code|component-header.qml}}) is the top navigation bar. It is passed:  
  
* {{code|currentRoute: router.currentRoute}} — used to highlight the active main-nav and sub-nav tabs and to determine the header state.  
* {{code|isInGame: appRoot.isInGame}} — used to enable/disable the Save Game sub-nav button.  
* {{code|hide: true}} — starts hidden; set to {{code|false}} by engine event handlers once the UI is ready.  
* {{code|visible: !appRoot.isLoadingLevel}} — completely hidden (not just off-screen) during level loads.  
  
The header has three states: {{code|hidden}}, {{code|subnav-closed}}, and {{code|subnav-open}}. State transitions are 250 ms {{code|NumberAnimation}} slides using {{code|Easing.OutQuint}}. The sub-nav row switches its {{code|ListModel}} based on the first path segment of {{code|currentRoute.path}} ({{code|campaign}}, {{code|multiplayer}}, {{code|options}}, {{code|steamworkshop}}).  
  
The header also executes <code><nowiki>BlackMesaEngine.executeClientCommandUnrestricted("exec server.cfg;")</nowiki></code> in the {{code|multiplayerNavModel.Component.onCompleted}} handler to pre-load server configuration when the multiplayer sub-nav model is first created.  
  
=====Router=====  
  
The {{code|Router}} ({{code|router.qml}}) fills the space between the header and footer. It receives {{code|isInGame: appRoot.isInGame}} and propagates three signals upward to {{code|main.qml}}:  
  
{| class="standard-table"  
! Signal  
! Handler in {{code|main.qml}}  
! Action  
|-  
| {{code|onLoadGameRequest}}  
| Sets {{code|footer.levelName}} to {{code|savegame.chapterName}}  
| Calls {{code|BlackMesaUtils.loadGame(savegame.savename)}}  
|-  
| {{code|onLoadMapRequest}}  
| Sets {{code|footer.levelName}} to {{code|mapname}}  
| Calls {{code|BlackMesaUtils.loadMap(filename)}}  
|-  
| {{code|onSaveGameRequest}}  
| Sets {{code|appRoot.isSaving [[=]] true}}, hides {{code|appRoot}}  
| Calls {{code|BlackMesaUtils.saveGame(filename, callback)}}; callback resets {{code|isSaving}}  
|}  
  
The save handler hides {{code|appRoot}} before saving so the menu overlay does not appear in the save thumbnail. A TODO comment acknowledges this as a hack requiring proper state management.  
  
=====Footer=====  
  
The {{code|Footer}} ({{code|component-footer.qml}}) is the bottom bar. It switches between two {{code|Component}} instances via a {{code|Loader}}:  
  
* '''{{code|menuFooter}}''' — shown when {{code|isLoading}} is {{code|false}}. Contains a compass icon, a Quit button, a Back/Back to Game button, a {{code|MenuNavGuide}}, and a Discord link.  
* '''{{code|loadingFooter}}''' — shown when {{code|isLoading}} is {{code|true}}. Contains a rotating loading quote (cycling every 5 seconds from {{code|L10n.strings.loading.quotes}}), a level name label, and a progress bar driven by {{code|loadPercent}}.  
  
The Quit button routes to {{code|Routes.savebeforequit}} when {{code|isInGame}} is {{code|true}}, or {{code|Routes.quit}} otherwise. The Back button routes to {{code|Routes.back}} (pop) when {{code|_showBackButton}} is {{code|true}}, or calls {{code|BlackMesaEngine.executeClientCommand('gameui_hide')}} when {{code|_showBackToGameButton}} is {{code|true}}.  
  
The Discord link opens {{code|BlackMesaUtils.discordLink}} via {{code|Qt.openUrlExternally}} after a 500 ms {{code|setTimeout}} delay (to allow the click sound to play first).  
  
====Binding Capture MouseArea====  
  
A full-screen {{code|MouseArea}} with {{code|z: 2000}} sits above all other content. It is {{code|enabled}} only when {{code|InputBindingsManager.isBinding}} is {{code|true}}. When active, it intercepts all mouse button clicks and scroll wheel events and forwards them to {{code|InputBindingsManager.handleBindingResponse}} with the appropriate key string from {{code|InputBindingsManager.mouseMap}}.  
  
====Engine Event Handlers====  
  
All engine signals are handled in a single {{code|Connections}} block targeting {{code|BlackMesaEngine}}, with {{code|ignoreUnknownSignals: true}} and {{code|enabled: !isMenuBlocked}}.  
  
=====onKeyCaptured=====  
  
Converts the raw {{code|keyButtonCode}} to a string via {{code|BlackMesaEngine.keyButtonCodeToString()}}. If {{code|InputBindingsManager.isBinding}} is {{code|true}}, forwards to {{code|handleBindingResponse}}. If a binding cell is selected and Escape is pressed, calls {{code|InputBindingsManager.clearSelection()}}.  
  
=====onGameUIActived=====  
  
Note: the signal name is {{code|onGameUIActived}} (missing the 't' in "Activated") — this matches the engine's signal name.  
  
# Calls {{code|BlackMesaEngine.grabInputForGameUI()}} to capture keyboard/mouse input.  
# Recomputes {{code|isInGame}}: {{code|true}} only if the engine reports in-game, {{code|_isInitialLoad}} is {{code|false}}, the level is not the main menu background, and no level is currently loading.  
# On the initial load, calls {{code|wallpaper.updateBackgroundImage()}} with the main menu background name.  
# If {{code|loadingErrorFlag}} is set, clears it and routes to {{code|Routes.multiplayer}} to show the server list after a failed connection.  
# Otherwise, if not currently loading and either this is the initial load or the UI was not already visible, unhides the header and routes to {{code|Routes.index}}.  
# Makes {{code|appRoot}} visible and forces active focus.  
# If single-player and in-game, executes {{command|setpause}} with {{code|nomsg}} to pause the game silently.  
  
=====onGameUIHidden=====  
  
# Resets {{code|didLoadLevel}} to {{code|false}}.  
# Closes the dev console.  
# Hides {{code|appRoot}}.  
# Hides the header (the footer fades with {{code|appRoot}} and does not need explicit hiding).  
# Routes to {{code|emptyRoute}}, passing {{code|didLoadLevel}} as the {{code|immediate}} flag — if {{code|true}}, the transition is instant (level just loaded); if {{code|false}}, the normal fade-out animation plays.  
# Calls {{code|BlackMesaEngine.releaseInputFromGameUI()}}.  
# If single-player and in-game, executes {{command|unpause}} with {{code|nomsg}}.  
  
=====onLevelLoadingStarted=====  
  
# Executes {{command|unpause}} with {{code|nomsg}}.  
# Determines {{code|shouldUpdateProgressBar}}: {{code|true}} if the engine's {{code|showProgressDialog}} flag is set, or if the level is the main menu background, or if the level name is empty.  
# If {{code|shouldUpdateProgressBar}} and the UI is already visible, manually fires {{code|BlackMesaEngine.gameUIActived()}} to trigger the {{code|onGameUIActived}} handler. This is acknowledged as a cross-handler hack.  
# Updates the wallpaper to the loading level's background.  
# Calls {{code|BlackMesaEngine.setShouldUpdateProgressBar(shouldUpdateProgressBar)}}.  
# Releases input, sets {{code|isInGame [[=]] false}}, {{code|isLoadingLevel [[=]] true}}, shows the wallpaper image, hides extras, stops the background music timer, routes to {{code|emptyRoute}} immediately, and hides the header.  
  
=====onLevelLoadingFinished=====  
  
The most complex handler. Receives {{code|isError}}, {{code|failureReason}}, {{code|showProgressDialog}}, and {{code|levelName}} as injected variables from the engine.  
  
# Clears {{code|_isInitialLoad}}, {{code|isLoadingLevel}}, sets {{code|didLoadLevel [[=]] true}}.  
# Recomputes {{code|isInGame}} and {{code|isInMultiplayerMode}}.  
# Resets {{code|loadPercent}} and {{code|footer.levelName}}.  
  
Then branches on three cases:  
  
{| class="standard-table"  
! Case  
! Condition  
! Actions  
|-  
| Load error  
| <code><nowiki>isError === true</nowiki></code>  
| Stores {{code|failureReason}}, shows {{code|alertLoadFailed}}, sets {{code|loadingErrorFlag [[=]] true}}, resets {{code|didLoadLevel}} and {{code|isInGame}} to {{code|false}}.  
|-  
| Main menu background loaded  
| <code><nowiki>isLevelMainMenuBackground</nowiki></code>

|-  
| Game level loaded

The "game level loaded" branch sets {{code|isInGame [[=]] false}} temporarily. The correct {{code|isInGame}} value is recomputed in the subsequent {{code|onGameUIActived}} call when the player opens the menu.  
  
=====onDisconnectedFromServer=====  
  
Updates both {{code|footer.isInGame}} and {{code|appRoot.isInGame}} from {{code|BlackMesaEngine.isInGame()}} filtered by {{code|isLevelMainMenuBackground()}}.  
  
=====onUpdateProgressValue=====  
  
Sets {{code|appRoot.loadPercent [[=]] progressValue}}. Drives the loading progress bar in {{code|loadingFooter}}.  
  
====autoBackgroundMusicTimer====  
  
A one-shot {{code|Timer}} with a 1250 ms interval that starts running immediately on construction. It is a fallback for the case where the engine never fires {{code|onLevelLoadingFinished}} (e.g., the UI is loaded without a level load event, or the engine starts in a state where the loading sequence is already complete).  
  
On trigger:  

1. Sets {{code|_isInitialLoad [[=]] false}} and {{code|isLoadingLevel [[=]] false}}.  

2. Unhides the header.  

3. Shows wallpaper extras.  

4. Routes to {{code|Routes.index}}.  

5. Updates the wallpaper.  

6. Calls {{code|Sound.startMusic()}}.  
  
The timer is stopped in {{code|onLevelLoadingStarted}} to prevent it from firing during a level load. A TODO comment describes this as "bitfucking".  
  
====alertLoadFailed====  
  
An inline {{code|Alert}} ({{code|component-alert.qml}}) shown when a level load fails (e.g., failed server connection). It uses {{code|BlackMesaEngine.getLocalizedString()}} directly for both its title ({{code|#BlackMesaUI_Error}}) and button label ({{code|#GameUI_OK}}), bypassing the {{code|L10n}} singleton. It has a single {{code|DefaultButton}} that resets {{code|levelLoadingFinished_FailureReason}} and calls {{code|alertLoadFailed.hide()}}.  
  
The {{code|Alert}} component itself ({{code|component-alert.qml}}) is a full-screen {{code|MouseArea}} that intercepts all pointer events to prevent click-through. It animates the modal panel in from {{code|y+300}} over 600 ms using {{code|Easing.InOutQuint}}, and out to {{code|y+300}} then immediately to {{code|y+30000}} (off-screen) on hide. On show, it calls {{code|BlackMesaUtils.traverseUIElements()}} and {{code|BlackMesaUtils.afterTraverseCallback()}} after a 450 ms delay to register the alert's buttons with the controller navigation system.  
  
====Notable Issues====  
  
1. '''{{code|onGameUIActived}} typo.''' The signal handler name is missing the 't' in "Activated". This matches the engine's signal name ({{code|gameUIActived}}), so it works correctly, but it is a persistent typo in both the engine and the QML layer.  
  
2. '''Cross-handler invocation in {{code|onLevelLoadingStarted}}.''' The handler manually calls {{code|BlackMesaEngine.gameUIActived()}} to trigger {{code|onGameUIActived}} under certain conditions. The comment acknowledges this as "not good" and explains that it is the reason for the complex conditional logic in {{code|onGameUIActived}}.  
  
3. '''{{code|isInGame}} is set to {{code|false}} in the "game level loaded" branch of {{code|onLevelLoadingFinished}}.''' This is a temporary state: the correct value is recomputed in the next {{code|onGameUIActived}}. However, between {{code|onLevelLoadingFinished}} and {{code|onGameUIActived}}, any code that reads {{code|appRoot.isInGame}} will see {{code|false}} even though the player is in-game.  
  
4. '''{{code|_isInitialLoad}} check in {{code|onLevelLoadingFinished}} line 301 is redundant.''' {{code|_isInitialLoad}} is set to {{code|false}} on the immediately preceding line, so the expression <code><nowiki>!_isInitialLoad && ...</nowiki></code> always evaluates to {{code|true && ...}}.  
  
5. '''{{code|autoBackgroundMusicTimer}} and {{code|onLevelLoadingFinished}} both clear {{code|_isInitialLoad}}.''' If the engine fires {{code|onLevelLoadingFinished}} normally, the timer fires 1250 ms later and redundantly re-runs the index routing and music start logic. The timer is not stopped in {{code|onLevelLoadingFinished}}.  
  
6. '''{{code|component-wallpaper.qml}} has mismatched widescreen file mappings.''' {{code|background06_widescreen}} maps to {{code|background02_widescreen.vtf}} (should be {{code|background06_widescreen.vtf}}). {{code|background09_widescreen}}, {{code|background10_widescreen}}, and {{code|background11_widescreen}} are each off by one index.  
  
7. '''{{code|component-wallpaper.qml}} references {{code|subNavBackground}} without the {{code|Theme.colors.}} prefix.''' The gradient stop on line 147 uses the bare identifier {{code|subNavBackground}}, which is not in scope. This resolves to {{code|undefined}}, making the gradient stop effectively transparent.  
  
8. '''{{code|alertLoadFailed}} bypasses {{code|L10n}}.''' Both the title and button label use {{code|BlackMesaEngine.getLocalizedString()}} directly, inconsistent with all other alert dialogs in the codebase.  
  
9. '''{{code|component-alert.qml}} positions the hidden modal at {{code|anchors.verticalCenterOffset: 30000}}.''' This is a hack to move the modal off-screen in the hidden state without using {{code|visible: false}} (which would prevent the show animation from running). The value 30000 is large enough to guarantee the modal is off-screen at any resolution.  
  
10. '''{{code|Connections}} block is disabled during menu animation.''' Setting {{code|enabled: !isMenuBlocked}} means that if the engine fires {{code|onGameUIHidden}} or {{code|onLevelLoadingStarted}} while the 625 ms open/close animation is playing, those signals are silently dropped. This is the intended behavior (to prevent visual artifacts from rapid ESC presses), but it means the UI can get into an inconsistent state if the engine fires critical signals during the animation window.

====Notable Issues====  
  
1. '''No explicit module declaration.''' A {{code|qmldir}} file can begin with a {{code|module}} directive (e.g. <code><nowiki>module com.crowbarcollective.blackmesa</nowiki></code>) to give the module a qualified import path. This file has none, meaning the module is identified only by its file system location and is imported implicitly by the engine rather than via an {{code|import}} statement.  
  
2. '''All versions are {{code|1.0}}.''' No component has been versioned beyond {{code|1.0}}. QML's versioning system allows older consumers to pin to a specific API version, but since all types share the same version, the versioning provides no practical isolation.  
  
3. '''{{code|BindingCell}} is registered but its sibling input types are not.''' {{code|component-optionslist-input-bindingcell.qml}} is registered as {{code|BindingCell 1.0}}, but the six other input types (slider, select, checkbox, map, binding, separator, text) are not registered. This inconsistency suggests {{code|BindingCell}} was promoted to a named type because it is also used directly by {{code|component-binding.qml}} outside of the {{code|OptionsListRow}} context, while the other input types are only ever used inside {{code|OptionsListRow}}.

===sound.qml===
Registered as the Sound singleton in qmldir. It is a pragma Singleton QtObject that wraps '''BlackMesaEngine''''s audio API into a clean, named interface for the rest of the UI.

====Properties====
*'''ambientId''' — a writable int that stores the handle returned by {{code|BlackMesaEngine.playAmbientSound}}, used to track and stop the currently playing ambient/music track.
*'''music''' — a readonly array of the two music track paths pulled from '''Theme.sounds.music1''' and '''Theme.sounds.music2'''.

====Functions====
*{{code|startMusic()}} - picks one of the two music tracks at random and calls {{code|startAmbient()}} with it.
*{{code|stopMusic()}} - delegates to {{code|stopAmbient()}}.
*{{code|playEffect(filestr)}} - plays a one-shot UI sound effect via '''BlackMesaEngine.playSoundEffect'''.
*{{code|isPlayingAmbient()}} - returns true if ambientId is non-null/non-zero.
*{{code|startAmbient(filestr)}} - stops any current ambient, reads [[snd_musicvolume]] from the console, then calls '''BlackMesaEngine.playAmbientSound''' and stores the returned ID in '''ambientId'''.
*{{code|stopAmbient()}} - if '''ambientId''' is set and the sound is still playing, stops it via '''BlackMesaEngine.stopSoundById''' and nulls '''ambientId'''.

====Bug====
There is a typo on line 41: '''ambiendId''' (extra d) instead of ambientId. This means {{code|stopAmbient()}} will throw a ReferenceError at runtime when it tries to stop a playing sound, so ambient tracks can never actually be stopped once started. sound.qml:39-44

====Usage across the codebase====
Sound is used in two distinct patterns.


Music lifecycle — startMusic/stopMusic are called from:
*'''main.qml''' (5 matches) — likely on '''gameui_activated'''/'''gameui_hidden''' signals.
*'''routeview-index.qml''' (6 matches) — starts/stops music when the main menu index page is entered/exited.
*'''component-footer.qml''' (4 matches) — manages music during the loading screen.


UI sound effects — '''playEffect''' is called from virtually every interactive component, passing '''Theme.sounds.buttonFocused''' on hover and '''Theme.sounds.buttonClicked''' on press:
*All button types: '''button-default.qml''', '''button-letterbox.qml''', '''button-triangle.qml''', '''button-carouselnav.qml'''.

===theme.qml===
Registered as the '''Theme''' singleton in qmldir and serves as the global design system for the entire UI — fonts, colors, opacities, sounds, and locale utilities all live here.

====Layout====
It is a pragma Singleton QtObject with multiple top-level members.

=====Scaling properties=====
'''rootWidth''', '''rootHeight''', '''widthScale''', and '''heightScale''' are writable properties (no readonly). They are set externally, in '''main.qml''', the primary source, using '''Binding''' elements for the scale properties and '''onWidthChanged'''/'''onHeightChanged''' handlers for the raw dimensions, and '''routeview-video.qml''' — directly reassigns all four when the user applies a resolution change from the video settings page, so the UI rescales immediately without waiting for a window resize event. Also used throughout the UI to scale elements to the current resolution. '''Triangle''' for example uses '''Theme.heightScale''' directly.

=====dictionary — locale map=====
A nested QtObject mapping '''Steam''' language names (e.g. "english", "schinese", "koreana") to BCP 47 locale codes (e.g. "en_US", "zh_CN", "ko_KR"). Used by '''getDateTimeString'''.

=====getDateTimeString(date) — locale-aware date formatter=====
Reads [[cl_language]] from the engine console, looks it up in dictionary, then formats the date using Qt's '''toLocaleString''' with a localized format string fetched from {{code|BlackMesaEngine.getLocalizedString}}.

=====colors — color palette=====
All named colors used across the UI:
*highlight	- #e47125 (orange).
*text/buttonText/headerText - white.
*dimmedText - #888888 (gray).
*subNavBackground - #111111 (black).
*skrim - #2d2d2d (dark gray).
*modalBackground - #222222 (darker gray).
*warning - #c72424 (red).
*navigationHighlight - #e88849 (lighter orange), for controller-focused active buttons.

=====opacity — named opacity levels=====
Seven named opacity values for different UI layers: subNav (0.5), mainNav (0.75), modal (0.95), modalHeader (0.85), modalSkrim (0.9), pageSkrimLight (0.75), pageSkrimDark (0.85).

=====sounds — UI sound effect paths=====
Four named sound paths: '''buttonFocused''', '''buttonClicked''', and two music tracks ('''music1''', '''music2'''). The music paths are prefixed with #.

=====fonts — font family strings=====
Loads six font files via '''FontLoader''' from the VFS ({{code|vfs:///ui/fonts/}}): Fira Mono (dev console), and NotoSans in Light/Bold/Regular plus their CJK variants. The public '''fonts.light''', '''fonts.bold''', and '''fonts.regular''' properties are comma-joined font family strings that list the CJK font first so it takes priority for CJK characters.

=====devConsole — dev console sub-theme=====
A nested color palette specifically for the developer console: background (#d0202020), message (lightgray), inputText (#ffd0d0d0). The '''fonts.devConsole''' property (Fira Mono) pairs with this.

===triangle.qml===
This a small, reusable primitive that renders a triangle shape using a rotated, clipped Rectangle. It is registered in qmldir as the Triangle component (not a singleton).

====How it works====
The component is an '''Item''' with {{code|clip: true}}. Inside it sits a '''Rectangle''' that is rotated 45° and scaled up by 1.4 * '''Theme.heightScale''', so only one corner of the rotated square peeks out through the clipping boundary — producing a triangle.

The position of that corner is controlled by the corner property (an integer, default 0). The x and y of the inner rectangle are calculated using modular arithmetic on corner to snap it to one of the four corners of the parent '''Item''' ('''triangle.qml''' around lines 14-15):

<source lang=qml>
x = component.width  * ((corner+1) % 4 < 2 ? 0 : 1) - width/2  
y = component.height * ( corner    % 4 < 2 ? 0 : 1) - height/2  
</source>

The color property is aliased directly to the inner '''rect.color''', so consumers can set it like any normal color property.

====Usage====
Triangle is used by '''button-triangle.qml''' ('''TriangleButton'''), which sets rotation on the '''Triangle''' instance to point it left or right, and animates its color between '''blurredColor''' and '''focusedColor''' on hover. 

===utils.qml===
Registered as the '''BlackMesaUtils''' singleton in qmldir and serves as the central utility and UI navigation hub for the entire menu system. Stores some utils and helpers.

====Structure Overview====
It is a pragma '''Singleton''' QtObject with two main responsibilities, save/load game helpers and controller/keyboard UI navigation.

====General Utilities====
*'''discordLink''' — a hardcoded string "https://discord.gg/crowbarcollective", used as invite link to [[Crowbar Collective]]'s server in '''Discord'''.
*{{code|setTimeout(cb, delay)}} — a polyfill for JavaScript's setTimeout, since Qt has no native equivalent. Uses a shared '''globalTimer''' and properly disconnects signals after firing.

====Save/Load Game Functions====
*{{code|getSaveGames()}} — calls {{code|BlackMesaEngine.listSaveEntries()}}, sorts by date descending, and maps each entry into a normalized object with '''savename''', '''chapter''', '''chapterName''', '''type''' ("manual", "autosave", or "quick"), '''dateCreated''', and '''thumbnail'''.
*{{code|saveGame(filename, callback)}} — auto-generates a zero-padded file name like ''bms-001'' if none is provided, then issues a {{code|gameui_hide;save}} engine command and calls back.
*{{code|loadGame(filename)}}/{{code|loadMap(filename)}} — issue {{code|disconnect;wait;wait;sv_cheats 0; maxplayers 1; load/map}} engine commands.

====UI Navigation System====
This is the bulk of the file. It implements a regex-based UI traversal and keyboard/controller navigation system.

=====State Properties=====
Tracks the current/previous focused element, a flat tabs array, indices for main/sub/sub-nav tab levels, '''actionButtons''' ('''APPLY''', '''CANCEL''', '''DISCARD''', '''QUIT''', '''BACK'''), and '''optionItems''' (list rows and carousel items).

=====Key Functions=====
*{{code|clearUIElementsData()}} - resets all navigation state before a screen transition.
*{{code|traverseUIElements(root)}} - recursively walks the QML tree, classifying elements by objectName regex into tabs, buttons, option items, or carousel items.
*{{code|afterTraverseCallback()}} - post-traversal: sets sub-tab start indices and focuses the first option item.
*{{code|processOptionSelection(sign)}}	- moves up/down through optionItems, skipping disabled ones.
*{{code|processCarouselItemSelection(sign)}} - moves left/right through carousel items, triggering pagination arrows as needed.
*{{code|processTabsNavigation(sign)}} - handles left/right navigation across 3 levels of tabs (main -> sub -> sub-nav).
*{{code|navigationUIHandle(event)}} - entry point called from {{code|Keys.onPressed}} in '''main.qml'''; dispatches all key events ('''Enter''', '''Backspace''', '''A'''/'''D''', arrows) to the above functions.
*{{code|updateCurrentUISelection()}} - applies "focused"/"blurred" states to elements and scrolls lists to keep the selection visible.

=====Navigation Priority (Backspace/Back button)=====
When backspace is pressed, it checks in order: in-game -> '''DISCARD''' -> '''CANCEL''' -> '''BACK''', giving a clear priority chain for controller "B button" behavior.
