===button-carouselnav.qml===

====Transitions====  
  
Both {{code|blurred}} → {{code|focused}} and {{code|focused}} → {{code|blurred}} animate {{code|image.opacity}} over 150 ms using a {{code|NumberAnimation}} wrapped inside a {{code|ParallelAnimation}}. The {{code|ParallelAnimation}} wrapper contains only a single child animation and is therefore redundant.

====Usage in component-carousel.qml====  
  
{{code|component-carousel.qml}} instantiates two {{code|CarouselButton}} items — one on each side of the clipping mask (id: {{code|mask}}).  
  
{| class="standard-table"

Each instance is hidden and disabled when its corresponding direction has no more items: <code><nowiki>enabled: showLeft</nowiki></code> / <code><nowiki>opacity: showLeft ? 1.0 : 0.0</nowiki></code>. The opacity fade is handled externally by a {{code|Behavior on opacity}} in the parent, independent of the internal state-based opacity on the image. This creates two stacked opacity layers: the button-level fade (parent-controlled) and the image-level hover fade (state-controlled).  
  
====Technical Notes====  
  
1. '''{{code|buttonHeight}} uses {{code|Theme.widthScale}}.''' The height dimension is computed as <code><nowiki>Math.ceil(214 * Theme.widthScale)</nowiki></code> rather than <code><nowiki>Math.ceil(214 * Theme.heightScale)</nowiki></code>. On non-16:9 displays where {{code|widthScale}} and {{code|heightScale}} differ, the button hit area will not scale correctly in the vertical axis.  
  
2. '''Image height also uses {{code|Theme.widthScale}}.''' The inner {{code|Image}} height is <code><nowiki>Math.ceil(sourceSize.height * Theme.widthScale)</nowiki></code>. Combined with {{code|fillMode: Image.PreserveAspectFit}}, the image will not be distorted, but the computed height value passed to the layout engine is incorrect on non-16:9 displays.  
  
3. '''{{code|scale}} alias is dead code.''' The {{code|scale}} property is aliased to {{code|image.scale}} and exposed as a public API, but no consumer in the codebase sets it. It is likely a leftover from an earlier design.  
  
4. '''{{code|ParallelAnimation}} wraps a single child.''' Both transitions use a {{code|ParallelAnimation}} containing exactly one {{code|NumberAnimation}}. The parallel wrapper provides no benefit and adds unnecessary nesting.  
  
5. '''{{code|onReleased}} vs {{code|onClicked}} for sound.''' The click sound is played in {{code|onReleased}} rather than {{code|onClicked}}. {{code|onClicked}} fires only when the press and release both occur within the {{code|MouseArea}}; {{code|onReleased}} fires unconditionally on any release. This is inconsistent with {{code|button-default.qml}} and {{code|button-letterbox.qml}}, which use {{code|onClicked}}.  
  
6. '''No {{code|objectName}}.''' Unlike {{code|DefaultButton}} ({{code|objectName: "ui:btn:action[...]"}}) and {{code|LetterboxButton}}, {{code|CarouselButton}} has no {{code|objectName}}. The {{code|BlackMesaUtils.traverseUIElements}} traversal called after carousel pagination in {{code|component-carousel.qml}} will not identify these buttons by name.  
  
7. '''No {{code|disabled}} property.''' The button has no internal disabled state. Disabling is handled entirely by the parent setting {{code|enabled: false}}, which suppresses all {{code|MouseArea}} events but does not change the visual appearance beyond the parent-controlled opacity fade.  
  
8. '''{{code|id: carouselButton}} is unused internally.''' The root id is declared but never referenced by any child element or internal binding within the file.  

===button-cta.qml===  
  
{{code|button-cta.qml}} implements the '''Call-to-Action''' (CTA) button variant used throughout the UI. It is a minimal subclass of {{code|DefaultButton}} that overrides three properties to produce a visually distinct primary-action button. Registered in {{code|qmldir}} as {{code|CTAButton 1.0}}.  
  
====Inheritance====  
  
{| class="standard-table"  
! Base class !! File  
|-  
| {{code|DefaultButton}} || {{code|button-default.qml}}  
|}  
  
{{code|CTAButton}} does not define any new properties, signals, functions, or child items. It consists entirely of three property overrides on {{code|DefaultButton}}.  
  
====Property Overrides====  
  
{| class="standard-table"  
! Property !! CTAButton value !! DefaultButton default !! Resolved value  
|-  
| {{code|bold}} || {{code|true}} || {{code|false}} || Uses {{code|Theme.fonts.bold}} (NotoSans Bold / NotoSansCJK Bold) instead of {{code|Theme.fonts.regular}}  
|-  
| {{code|boxColor}} || <code><nowiki>Theme.colors.highlight</nowiki></code> || <code><nowiki>Theme.colors.buttonText</nowiki></code> || {{code|#e47125}} (orange) instead of {{code|white}}  
|-  
| {{code|focusedTextColor}} || <code><nowiki>Theme.colors.buttonText</nowiki></code> || <code><nowiki>Theme.colors.highlight</nowiki></code> || {{code|white}} instead of {{code|#e47125}} (orange)  
|}  
  
The net effect is an inversion of the DefaultButton color scheme: where {{code|DefaultButton}} uses a white border/fill with orange focused text, {{code|CTAButton}} uses an orange border/fill with white focused text.  
  
====Effective Visual States====  
  
All state logic is inherited from {{code|DefaultButton}}. The overridden properties change the resolved colors as follows:  
  
{| class="standard-table"  
! State !! Border color !! {{code|focusShape}} fill !! Text color !! {{code|focusShape}} height  
|-  
| {{code|blurred}} || {{code|#e47125}} || {{code|#e47125}} || {{code|white}} || <code><nowiki>Math.ceil(8 * Theme.heightScale)</nowiki></code> (bottom bar only)  
|-  
| {{code|focused}} || {{code|#e47125}} || {{code|#e47125}} || {{code|white}} || Full button height (solid orange fill)  
|-  
| {{code|disabled}} || {{code|#888888}} || {{code|#888888}} || {{code|#888888}} || <code><nowiki>Math.ceil(8 * Theme.heightScale)</nowiki></code> (bottom bar only)  
|}  
  
In the {{code|blurred}} state the button appears as an orange-bordered rectangle with a thin orange bottom bar and white text. In the {{code|focused}} state the entire button fills with orange and the text remains white. The {{code|disabled}} state is identical to {{code|DefaultButton}}: all elements use {{code|Theme.colors.dimmedText}} ({{code|#888888}}).  
  
The {{code|blurredTextColor}} property is not overridden, so blurred text color remains {{code|Theme.colors.buttonText}} ({{code|white}}), which is the same as {{code|focusedTextColor}}. Text color does not change between blurred and focused states in {{code|CTAButton}}.

====Notable Observations====  
  
1. '''{{code|focusedTextColor}} override is redundant.''' {{code|DefaultButton}} sets <code><nowiki>focusedTextColor: Theme.colors.highlight</nowiki></code> (orange). {{code|CTAButton}} overrides it to <code><nowiki>Theme.colors.buttonText</nowiki></code> (white). However, since {{code|blurredTextColor}} is also white and text color does not animate between blurred and focused states in {{code|CTAButton}}, the override has no visible effect — the text is white in both states regardless. The override is nonetheless necessary to prevent orange text from appearing on the orange {{code|focusShape}} fill during the focused state.  
  
2. '''Semantic inversion in quit/save-before-quit dialogs.''' In {{code|routeview-quit.qml}}, {{code|CTAButton}} is used for the destructive "Quit" action and {{code|DefaultButton}} for the safe "Cancel" action. In {{code|routeview-savebeforequit.qml}}, {{code|CTAButton}} is used for "Cancel" and "Don't Save" while {{code|DefaultButton}} is used for "Save". The CTA styling (orange, bold) does not consistently indicate a constructive or safe action — it marks the contextually primary action, which may be destructive.  
  
3. '''The file is 8 lines including imports.''' The entire implementation is three property assignments. All layout, animation, state, and interaction logic is inherited from {{code|DefaultButton}} without modification.  
  
4. '''No {{code|objectName}} is set at the type level.''' Individual instances set {{code|objectName}} (e.g. {{code|"ui:btn:action[apply]"}}, {{code|"ui:btn:action[cancel]"}}) at the call site. The type itself provides no default {{code|objectName}}, consistent with {{code|DefaultButton}} and {{code|WarningButton}}.  
  
5. '''{{code|bold: true}} is the only typographic override.''' All font size, capitalization ({{code|Font.AllUppercase}}), and family fallback logic remain in {{code|DefaultButton}}. The bold weight is the only typographic distinction between {{code|CTAButton}} and an unstyled {{code|DefaultButton}}.

===button-default.qml===

====Visual Structure====  
  
Three child items are declared directly under the outer {{code|MouseArea}}:  
  
; {{code|border}} ({{code|Rectangle}})  
: Fills the parent. Transparent fill; colored border of width {{code|borderWidth}} using {{code|boxColor}}. Has a standalone <code><nowiki>Behavior on border.color</nowiki></code> ({{code|ColorAnimation}}, 150 ms) that runs independently of the state machine.  
  
; {{code|focusShape}} ({{code|Rectangle}})  
: Anchored to the bottom, left, and right of the parent. Its {{code|height}} animates between {{code|focusShapeHeightBlurred}} (8 px scaled, blurred/disabled) and {{code|parent.height}} (full fill, focused). Color is {{code|boxColor}} or {{code|disabledBoxColor}}. This produces the "fill from bottom" hover effect.  
  
; {{code|buttonText}} ({{code|Text}})  
: Centered in the parent. Text is {{code|Font.AllUppercase}}. In the {{code|blurred}} state its {{code|anchors.verticalCenterOffset}} is set to {{code|buttonTextVerticalCenterOffsetBlurred}} (−4 px scaled), shifting it slightly upward above the {{code|focusShape}} underline. On focus the offset returns to {{code|0}}.

====Event Handlers====  
  
=====Inner {{code|mouseArea}}=====  
  
; {{code|onEntered}}  
: If state is not {{code|"disabled"}}, sets state to {{code|"focused"}}.  
  
; {{code|onExited}}  
: If state is not {{code|"disabled"}}, sets state to {{code|"blurred"}}.  
  
; {{code|onClicked}}  
: If not disabled, plays {{code|button.clickedSoundPath}} and sets <code><nowiki>mouse.accepted = false</nowiki></code> (propagates the event). If disabled, sets <code><nowiki>mouse.accepted = true</nowiki></code> inside the {{code|else}} branch, but this is immediately overwritten by the unconditional <code><nowiki>mouse.accepted = false</nowiki></code> on the next line. See [[#Known Issues and Observations|Known Issues]].  
  
=====Outer {{code|button}}=====  
  
; {{code|onDisabledChanged}}  
: Directly sets {{code|mouseArea.state}}. If {{code|disabled}} is {{code|true}}, forces state to {{code|"disabled"}}. Otherwise, checks {{code|button.containsMouse}} to decide between {{code|"focused"}} and {{code|"blurred"}}.

====Known Issues and Observations====  
  
1. '''Disabled click suppression is broken.''' The {{code|onClicked}} handler sets <code><nowiki>mouse.accepted = true</nowiki></code> inside the {{code|else}} (disabled) branch, but the unconditional <code><nowiki>mouse.accepted = false</nowiki></code> immediately following overwrites it. Clicks always propagate to parent items regardless of the {{code|disabled}} state.  
  
2. '''{{code|buttonWidth}} uses {{code|heightScale}} for horizontal padding.''' The formula is <code><nowiki>Math.ceil(buttonText.contentWidth + 46 * Theme.heightScale)</nowiki></code>. The 46-pixel padding is scaled by {{code|heightScale}} rather than {{code|widthScale}}, making the button narrower than expected on displays where the two scale factors differ (non-16:9 resolutions). {{code|borderWidth}} correctly uses {{code|widthScale}}.  
  
3. '''Nested {{code|MouseArea}} pattern.''' The root element is itself a {{code|MouseArea}} ({{code|button}}), and a second {{code|MouseArea}} ({{code|mouseArea}}) is nested inside it. The outer area serves only as a container and {{code|onDisabledChanged}} handler; all interactive logic lives in the inner area. This is an unusual pattern that could cause unexpected event routing if the outer area's own {{code|onClicked}} were ever connected.  
  
4. '''{{code|StateChangeScript}} fires on programmatic state changes.''' The {{code|focusedScript}} in the {{code|focused}} state plays the hover sound whenever the state becomes {{code|"focused"}}, including when {{code|onDisabledChanged}} programmatically sets {{code|mouseArea.state [[=]] "focused"}} because the cursor happens to be over the button at the moment it is re-enabled.  
  
5. '''{{code|Behavior on border.color}} is independent of the state machine.''' The {{code|border}} rectangle has a standalone {{code|Behavior}} that animates its {{code|border.color}} over 150 ms. The state machine also sets {{code|border.color}} via {{code|PropertyChanges}}. Both mechanisms run concurrently, which can cause the border color to animate twice or produce a double-transition artifact when states change rapidly.  
  
6. '''No {{code|objectName}} on the root element.''' Unlike most interactive components in the codebase (e.g. {{code|component-carousel-item.qml}} with {{code|objectName: "ui:carousel-item"}}), {{code|button-default.qml}} does not set an {{code|objectName}} on the root. ====Observations====  
  
1. '''{{code|focusedColor}} and {{code|selectedColor}} are semantically swapped.''' {{code|focusedColor}} (orange) is applied in the {{code|selected}} state; {{code|selectedColor}} (white) is applied in the {{code|focused}} (hover) state. This naming inversion is inherited by {{code|MainNavButton}}, which sets <code><nowiki>focusedColor: Theme.colors.buttonText</nowiki></code> and <code><nowiki>selectedColor: Theme.colors.highlight</nowiki></code> — the opposite of the base defaults — to achieve the correct visual result for main-nav buttons.  
  
2. '''Three horizontal dimension properties use {{code|Theme.heightScale}}.''' {{code|buttonWidth}}, {{code|focusShapeWidthFocused}}, and {{code|focusShapeMargin}} all multiply by {{code|Theme.heightScale}} instead of {{code|Theme.widthScale}}. On non-16:9 displays where the two scale factors differ, the button width and focus shape will not scale correctly relative to the horizontal axis.  
  
3. '''The root element is a {{code|MouseArea}}.''' The outer {{code|MouseArea}} ({{code|button}}) is used solely to expose {{code|containsMouse}} for state recovery in {{code|onSelectedChanged}} and {{code|onDisabledChanged}}, and to serve as the click target for consumers. All interaction logic lives in the inner {{code|mouseArea}}. Using {{code|Item}} as the root with an explicit {{code|containsMouse}} property would be cleaner and avoid the ambiguity of two nested {{code|MouseArea}} elements.  
  
4. '''No {{code|selected}} → {{code|focused}} transition.''' When a button is deselected while the mouse is hovering, {{code|onSelectedChanged}} sets the state directly to {{code|"focused"}} without an animated transition. The {{code|focusShape}} jumps from bar height to full height instantly.  
  
5. '''{{code|selected}} → {{code|blurred}} uses {{code|Easing.Linear}}.''' All other transitions specify {{code|Easing.OutQuint}}. The deselection animation (100 ms, linear) is noticeably faster and less smooth than the focus-in animation (250 ms, OutQuint).  
  
6. '''{{code|onClicked}} and {{code|StateChangeScript}} both reference sound playback, but the direct calls are commented out.''' The {{code|onEntered}} handler has a commented-out {{code|Sound.playEffect(button.focusedSoundPath)}} call, and {{code|onClicked}} has a commented-out {{code|Sound.playEffect(button.clickedSoundPath)}} call. Sound is played exclusively through the {{code|StateChangeScript}} blocks inside the {{code|focused}} and {{code|selected}} states. The commented-out calls are dead code.  
  
7. '''{{code|buttonHeight}} defaults to 63 px (scaled), not 64 px.''' The 1 px discrepancy is acknowledged in {{code|component-header.qml}} with a TODO comment noting that the logo image is 63 px and should be 64 px. {{code|MainNavButton}} overrides {{code|height}} to {{code|Math.ceil(64 * Theme.heightScale)}} to match the intended header height.

====Technical Notes====  
  
1. '''{{code|focusedColor}} and {{code|blurredColor}} produce the same text color in {{code|blurred}} state.''' {{code|blurredColor}} is not overridden and remains {{code|Theme.colors.buttonText}} (white). {{code|focusedColor}} is also set to {{code|Theme.colors.buttonText}} (white). The text color therefore does not change between {{code|blurred}} and {{code|focused}} states — only the {{code|focusShape}} geometry animates. The visual distinction between blurred and focused is entirely the white background bar appearing behind the text.  
  
2. '''The {{code|focused}} state renders white text on a white background.''' In the {{code|focused}} state, {{code|focusShape}} expands to full button height with {{code|color: button.focusedColor}} (white) and {{code|opacity: 1}}. The text color is {{code|selectedColor}} (orange). The result is orange text on a white background bar, which is the intended hover appearance.  
  
3. '''{{code|height}} override is 1 px taller than {{code|buttonHeight}}.''' {{code|LetterboxButton}} defines {{code|buttonHeight: Math.ceil(63 * Theme.heightScale)}} and sets {{code|height: buttonHeight}}. {{code|MainNavButton}} overrides {{code|height}} directly to <code><nowiki>Math.ceil(64 * Theme.heightScale)</nowiki></code>, bypassing {{code|buttonHeight}}. The {{code|buttonHeight}} property still exists on the instance with its original value of 63 scaled px, creating a silent discrepancy between {{code|buttonHeight}} and the actual rendered height.  
  
4. '''No {{code|blurred}} → {{code|selected}} transition.''' When the router sets a route on startup ({{code|Component.onCompleted}}), the button transitions directly from {{code|blurred}} to {{code|selected}} with no animation. This is correct behaviour for initial load but means the first navigation after startup also has no animation if the button was never hovered.  
  
5. '''{{code|type: "main"}} is a readonly inline property.''' The {{code|type}} property set on the delegate is not declared on {{code|MainNavButton}} or {{code|LetterboxButton}}; it is an ad-hoc property added at the instantiation site. It is used by {{code|utils.qml}} to identify main-nav buttons during keyboard/controller UI traversal.

====Notable observations====  
  
1. '''No {{code|disabled}} state.''' {{code|DefaultButton}} has an explicit {{code|disabled}} state with dimmed colors. {{code|TriangleButton}} only handles {{code|onEnabledChanged}} by forcing the state to {{code|blurred}}, leaving the triangle white rather than dimmed. The consumer hides the button entirely via {{code|opacity: 0}} when disabled, so this is not visible in practice, but the component itself provides no disabled visual feedback.  
  
2. '''No click sound.''' {{code|TriangleButton}} plays {{code|Theme.sounds.buttonFocused}} on hover but emits no sound on click. The consumer is responsible for playing {{code|Theme.sounds.buttonClicked}} in its own {{code|onClicked}} handler. This is the inverse of {{code|DefaultButton}}, which plays the click sound internally.  
  
3. '''Default dimensions are unscaled.''' {{code|width: 30}}, {{code|triangleHeight: 20}}, and {{code|triangleWidth: 20}} are all raw pixel values with no {{code|Theme.widthScale}} or {{code|Theme.heightScale}} multiplication. Every consumer must override these properties to achieve correct scaling.  
  
4. '''Double-scaling risk on {{code|triangle.qml}}.''' The {{code|Rectangle}} inside {{code|triangle.qml}} applies <code><nowiki>scale: 1.4 * Theme.heightScale</nowiki></code>. If the consumer also scales {{code|triangleHeight}} and {{code|triangleWidth}} by {{code|Theme.heightScale}}, the rendered triangle is effectively scaled twice: once by the Item dimensions and once by the internal {{code|scale}} factor. At {{code|heightScale}} values significantly above 1.0 this may cause the triangle to overflow its clipping bounds.  
  
5. '''{{code|corner}} property on {{code|Triangle}} is dead code in this context.''' {{code|TriangleButton}} never sets {{code|corner}}; it always remains {{code|0}} (top-left). All four orientations are achieved by rotating the entire {{code|Triangle}} item via {{code|rotation: direction}}. The {{code|corner}} property exists on {{code|triangle.qml}} for potential standalone use but is unused by its only registered consumer.  
  
6. '''{{code|direction}} accepts any integer.''' The {{code|directions}} QtObject provides named constants, but {{code|direction}} is a plain writable {{code|int}}. Passing an arbitrary angle produces a triangle pointing in that direction, which is a valid use case but is undocumented.  
  
7. '''{{code|anchors.horizontalCenterOffset}} is hardcoded to ±5.''' The offset is not scaled by {{code|Theme.widthScale}}. At high display scales the visual centering of the triangle within the button area will be slightly off.

====Notable Issues====  
  
1. '''Text color is identical in blurred and focused states.''' The explicit override <code><nowiki>focusedTextColor: Theme.colors.buttonText</nowiki></code> sets the focused text color to white, which is the same as the inherited {{code|blurredTextColor}}. The only visual change on hover is the {{code|focusShape}} fill expanding. In {{code|DefaultButton}}, the focused text color is {{code|Theme.colors.highlight}} (orange), which provides a distinct color cue; {{code|WarningButton}} suppresses this. The intent is presumably to keep white text readable against the red fill, but it eliminates the text-color transition animation entirely.  
  
2. '''{{code|bold}} is hardcoded and cannot be overridden by consumers.''' QML property bindings set in a subtype can be overridden by the instantiating parent, but since {{code|bold: true}} is a direct assignment in the component definition, any consumer that sets {{code|bold: false}} will override it. In practice no consumer does this, but the property is not {{code|readonly}}, so the hardcoding is implicit rather than enforced.  
  
3. '''Disabled appearance is identical to a disabled {{code|DefaultButton}}.''' The {{code|disabledBoxColor}} and {{code|disabledTextColor}} properties are not overridden, so a disabled {{code|WarningButton}} renders in {{code|#888888}} gray — the same as any other disabled button. There is no visual indication that the disabled button was a warning-type action.  
  
4. '''No {{code|id}} on the root element.''' Consistent with {{code|DefaultButton}}, the root {{code|MouseArea}} has {{code|id: button}} in the base class, but {{code|button-warning.qml}} does not re-declare an id. Child elements of {{code|WarningButton}} instances cannot reference the root by a {{code|WarningButton}}-specific id.  
  
5. '''{{code|boxColor}} is not {{code|readonly}}.''' Consumers can override {{code|boxColor}} after instantiation, which would change the border and fill color away from red. No consumer currently does this, but the warning semantics of the type are not structurally enforced.
