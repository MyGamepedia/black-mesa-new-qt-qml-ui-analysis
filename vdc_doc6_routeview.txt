This page contains information about routeview prefix QML {{bms|4}} files and their code from Resonance Decade Update. Also includes: route.qml, router.qml, routes.qml, routeview.qml.

===route.qml===  
  
{{code|route.qml}} is the '''Route data component'''. It defines the {{code|Route}} type used by {{code|routes.qml}} to declare every named navigation destination in the menu system. It is registered in {{code|qmldir}} as {{code|Route 1.0}}.  
  
{{code|Route}} is a pure data object — it has no visual content and emits no signals. All 22 route instances in {{code|routes.qml}} are {{code|readonly property Route}} children of the {{code|Routes}} singleton.

====How each property is consumed====  
  
=====name=====  
  
{{code|router.qml}} looks up routes by name via <code><nowiki>Routes[newRouteName]</nowiki></code>. After a push or replace, {{code|route.name}} is written to the new {{code|RouteView}}'s {{code|routeName}} property. After a pop, {{code|currentRoute}} is restored by reading <code><nowiki>Routes[outlet.currentItem.routeName]</nowiki></code>.  
  
{{code|name}} is also compared directly in transition logic: <code><nowiki>route.name === Routes.back.name</nowiki></code>, <code><nowiki>route.name === Routes.empty.name</nowiki></code>, <code><nowiki>currentRoute.name === Routes.index.name</nowiki></code>.  
  
=====path=====  
  
Used only by {{code|component-header.qml}} in three ways:  
  
{| class="standard-table"  
! Expression  
! Purpose  
|-  
| <code><nowiki>currentRoute.path.indexOf('.') === -1</nowiki></code>  
| Determines whether to show the sub-nav bar. A path with no dot (e.g. {{code|"index"}}, {{code|"achievements"}}) means no sub-nav; a dotted path (e.g. {{code|"campaign.newgame"}}) means show sub-nav.  
|-  
| <code><nowiki>currentRoute.path.split('.')[0] === routeName</nowiki></code>  
| Determines which main nav tab (Campaign, Multiplayer, Options, etc.) is highlighted as {{code|selected}}.  
|-  
| <code><nowiki>currentRoute.path.split('.')[1] === routeName</nowiki></code>  
| Determines which sub-nav tab (New Game, Load Game, etc.) is highlighted as {{code|selected}}.  
|}  
  
=====alert=====  
  
Checked in three places:  
  
1. {{code|router.qml}} — {{code|_getRouteTransitionConfig}} uses the {{code|up}} transition for alert routes and always uses {{code|push}} (never {{code|replace}}). When going back from an alert route, the {{code|down}} transition is used instead of {{code|up}}.  

2. {{code|component-header.qml}} — {{code|setState()}} sets the header state to {{code|"hidden"}} when <code><nowiki>currentRoute.alert</nowiki></code> is {{code|true}}, hiding both the main nav and sub-nav bars.  

3. {{code|component-optionslist.qml}} — checks {{code|currentRoute.alert}} to suppress the settings-flush confirmation when an alert is active.  
  
=====action=====  
  
Checked in {{code|router.qml}} after passthrough resolution and same-route deduplication, but before transition logic. If {{code|route.action}} is non-empty, the router calls <code><nowiki>actions[route.action]()</nowiki></code> and returns without modifying the stack or {{code|currentRoute}}. The only defined action is {{code|OPEN_STEAMWORKSHOP}}, which opens the Steam Workshop overlay via {{code|BlackMesaEngine.activateSteamOverlayToWebPage}}.  
  
=====passthrough / destination=====  
  
The first check in {{code|setRoute()}}. If <code><nowiki>route.passthrough</nowiki></code> is {{code|true}}, the local {{code|route}} variable is immediately replaced with <code><nowiki>Routes[route.destination]</nowiki></code>. All subsequent logic (same-route check, action check, transition config, push/replace) operates on the resolved destination route, not the passthrough route. The passthrough route itself is never pushed onto the stack and never becomes {{code|currentRoute}}.  
  
=====rank=====  
  
Used only in the {{code|else}} branch of {{code|_getRouteTransitionConfig}}, which is reached when both the current and new routes are non-alert, non-index, non-empty, and non-back. In this case the router uses {{code|replace}} (not {{code|push}}) and selects a horizontal slide direction based on rank comparison. Higher rank = further right in the conceptual hierarchy. Navigating to a higher-rank route slides left (new content enters from the right); navigating to a lower-rank route slides right.  
  
The rank values assigned in {{code|routes.qml}} are:  
  
{| class="standard-table"  
! Route group  
! Routes and ranks  
|-  
| Campaign  
| {{code|campaign}} 1.0, {{code|newgame}} 1.1, {{code|loadgame}} 1.2, {{code|savegame}} 1.3  
|-  
| Multiplayer  
| {{code|multiplayer}} 2.0, {{code|join}} 2.1, {{code|host}} 2.2  
|-  
| Options  
| {{code|options}} 3.0, {{code|game}} 3.1, {{code|input}} 3.2, {{code|bindings}} 3.3, {{code|video}} 3.4, {{code|audio}} 3.5, {{code|policy}} 3.6, {{code|translators}} 3.7  
|-  
| Achievements  
| {{code|achievements}} 4.0  
|-  
| Workshop  
| {{code|steamworkshop}} 5.0, {{code|addons}} 5.1, {{code|browse}} 5.2  
|-  
| Special (no rank / 0.0)  
| {{code|back}}, {{code|empty}}, {{code|index}}, {{code|quit}}, {{code|savebeforequit}}  
|}  
  
====Notable Issues====  

1. '''{{code|anchors.fill: parent}} on a data object.''' {{code|Route}} extends {{code|Item}} and sets {{code|anchors.fill: parent}}, making each {{code|Route}} instance a full-screen visual item parented to the {{code|Routes}} singleton {{code|Item}}. Since {{code|Route}} renders nothing, this is unnecessary overhead. The commented-out {{code|// width: parent.width}} and {{code|// height: parent.height}} lines suggest {{code|anchors.fill}} was a later substitution. A {{code|QtObject}} base would be more appropriate for a pure data type.  
  
2. '''{{code|action}} and {{code|qmlFile}} are mutually exclusive but not enforced.''' If both are set on a route, {{code|action}} takes priority and {{code|qmlFile}} is silently ignored. No validation or warning is produced.  
  
3. '''{{code|passthrough}} and {{code|action}} interaction is undefined.''' If a route has both {{code|passthrough: true}} and {{code|action}} set, the passthrough is resolved first, then {{code|action}} is checked on the ''resolved'' route — not the original. The {{code|action}} on the passthrough route itself is never evaluated.  
  
4. '''{{code|back}} is a sentinel, not a real route.''' {{code|Routes.back}} has only {{code|name: "back"}} set. It has no {{code|path}}, {{code|qmlFile}}, {{code|rank}}, or any other property. The router detects it by name comparison before any other logic and converts it to a {{code|pop}} operation. It is never pushed onto the stack and never becomes {{code|currentRoute}}.  
  
5. '''{{code|rank}} is a {{code|real}}, not an {{code|int}}.''' This allows fractional ranks (e.g. {{code|1.1}}, {{code|3.4}}) to express ordering within a group without requiring a global sequential integer scheme. However, ranks across groups (e.g. navigating from {{code|audio}} rank 3.5 to {{code|achievements}} rank 4.0) will also produce a left-slide transition, which may not always be the intended visual direction for cross-group navigation.

===router.qml===  
  
{{code|router.qml}} is the '''central navigation controller''' for the entire menu system. It is registered in {{code|qmldir}} as {{code|Router 1.0}} (not a singleton) and instantiated once in {{code|main.qml}} as {{code|Router { id: router }}}. It extends {{code|StackView}} from {{code|QtQuick.Controls 2.2}}, using the stack to manage the lifecycle of {{code|RouteView}} instances.

{| class="standard-table"  
! Property  
! Type  
! Description  
|-  
| {{code|currentRoute}}  
| {{code|Route}}  
| The {{code|Route}} object corresponding to the currently active view. Updated by {{code|setRoute()}} after every successful navigation.  
|-  
| {{code|isInGame}}  
| {{code|bool}}  
| Bound to {{code|appRoot.isInGame}} in {{code|main.qml}}. Passed to each new {{code|RouteView}} as a construction-time property.  
|}  
  
====Signals====  
  
Three signals are declared on the router and re-emitted upward to {{code|main.qml}}, which handles the actual engine calls:  
  
{| class="standard-table"  
! Signal  
! Handler in {{code|main.qml}}  
|-  
| <code><nowiki>saveGameRequest(string filename)</nowiki></code>  
| Hides {{code|appRoot}}, calls {{code|BlackMesaUtils.saveGame(filename, callback)}}, restores visibility in the callback.  
|-  
| <code><nowiki>loadGameRequest(variant savegame)</nowiki></code>  
| Sets {{code|footer.levelName}} to {{code|savegame.chapterName}}, calls {{code|BlackMesaUtils.loadGame(savegame.savename)}}.  
|-

====Initialization====  
  
{{code|Component.onCompleted}} calls <code><nowiki>outlet.setRoute(emptyRoute.name)</nowiki></code>. {{code|emptyRoute}} is not defined in {{code|router.qml}}; it resolves from the parent scope in {{code|main.qml}} where <code><nowiki>readonly property Route emptyRoute: Routes.empty</nowiki></code> is declared. This is an implicit scope dependency.  
  
====actions====  
  
A plain JavaScript object mapping action name strings to zero-argument functions. Currently contains one entry:  
  
{| class="standard-table"  
! Key  
! Behaviour  
|-  
| {{code|OPEN_STEAMWORKSHOP}}  
| Calls <code><nowiki>BlackMesaEngine.activateSteamOverlayToWebPage("https://steamcommunity.com/app/362890/workshop")</nowiki></code>.  
|}  
  
When {{code|setRoute()}} encounters a {{code|Route}} with a non-empty {{code|action}} property, it looks up the action by name in this object and calls it instead of performing a stack transition.

====_getRouteTransitionConfig====  
  
Determines the {{code|StackView}} operation ({{code|push}}, {{code|pop}}, or {{code|replace}}), the animation transition pair, and the construction-time properties to pass to the new {{code|RouteView}}. Returns a plain JavaScript config object.  
  
=====Transition selection logic=====  
  
Evaluated in order; the first matching branch wins:  
  
{| class="standard-table"  
! Condition  
! Stack operation  
! Transition  
|-  
| No {{code|currentRoute}} (initial navigation)  
| {{code|push}}  
| {{code|down}}  
|-  
| <code><nowiki>route.name === Routes.back.name</nowiki></code>  
| {{code|pop}}  
| {{code|down}} if current route is an alert; {{code|up}} otherwise  
|-  
| <code><nowiki>route.alert === true</nowiki></code> or <code><nowiki>route.name === Routes.empty.name</nowiki></code>  
| {{code|push}}  
| {{code|up}}  
|-  
| <code><nowiki>currentRoute.name === Routes.index.name</nowiki></code> or <code><nowiki>route.name === Routes.empty.name</nowiki></code>  
| {{code|push}}  
| {{code|down}}  
|-  
| <code><nowiki>currentRoute.name === Routes.empty.name</nowiki></code>  
| {{code|push}}  
| {{code|down}}  
|-  
| All other cases (rank-based lateral navigation)  
| {{code|replace}}  
| {{code|right}} if <code><nowiki>currentRoute.rank > route.rank</nowiki></code>; {{code|left}} otherwise  
|}  
  
The {{code|operation}} field is set to {{code|StackView.Immediate}} when {{code|skipTransition}} is {{code|true}} (used during level loading), and {{code|StackView.Transition}} otherwise.  
  
The {{code|properties}} field always contains <code><nowiki>{ routeName: route.name, isInGame: outlet.isInGame }</nowiki></code>, which are passed as construction-time properties to the new {{code|RouteView}}.  
  
====setRoute====  
  
The main public entry point for all navigation. Signature: <code><nowiki>setRoute(newRouteName, skipTransition, allowSameRoute)</nowiki></code>.  
  
Execution order:  
  
# Look up <code><nowiki>route = Routes[newRouteName]</nowiki></code>.  
# If {{code|route.passthrough}} is {{code|true}}, replace {{code|route}} with <code><nowiki>Routes[route.destination]</nowiki></code>.  
# If {{code|!allowSameRoute}} and the requested route is already the current route, return early (no-op).  
# If {{code|outlet.currentItem}} has an {{code|onRouteWillChange}} function, call it with {{code|newRouteName}}. If it returns {{code|true}}, the navigation is intercepted and {{code|setRoute}} returns. (Used by {{code|routeview-video.qml}} to show the unsaved-changes dialog.)  
# If {{code|route.action}} is non-empty, call <code><nowiki>actions[route.action]()</nowiki></code> and return. No stack transition occurs.  
# Call {{code|_getRouteTransitionConfig}} to determine the config.  
# Execute the stack operation:  
#* '''pop''': Sets {{code|popEnter}}/{{code|popExit}}, calls {{code|outlet.pop(operation)}}, then sets {{code|currentRoute}} from {{code|outlet.currentItem.routeName}}.  
#* '''push''' or '''replace''': Sets the corresponding {{code|pushEnter}}/{{code|pushExit}} or {{code|replaceEnter}}/{{code|replaceExit}} properties, calls <code><nowiki>outlet[fn](route.qmlFile, properties, operation)</nowiki></code>, then sets {{code|currentRoute = route}}.  
# Connects {{code|routeRequest}}, {{code|loadGameRequest}}, {{code|loadMapRequest}}, and {{code|saveGameRequest}} on {{code|outlet.currentItem}} to the four private handler functions.  
  
====parseRouteUIItems====  
  
Called from a {{code|ScriptAction}} at the end of every enter transition. Calls {{code|BlackMesaUtils.traverseUIElements(appRoot)}} followed by {{code|BlackMesaUtils.afterTraverseCallback()}} to rebuild the keyboard/controller navigation state for the newly visible view. {{code|appRoot}} is resolved from the parent scope in {{code|main.qml}} (implicit scope dependency).  
  
====routeTransitions====  
  
A readonly {{code|QtObject}} containing four named transition pairs. Each pair has an {{code|enter}} and an {{code|exit}} {{code|Transition}} reference:  
  
{| class="standard-table"  
! Name  
! Enter: slides in from  
! Exit: slides out to  
! Position axis  
! Duration  
|-  
| {{code|down}}  
| Top (y: −300 → 0)  
| Bottom (y: 0 → 300)  
| Y  
| 600 ms (position), 300 ms (opacity, delayed 300 ms)  
|-  
| {{code|up}}  
| Bottom (y: 300 → 0)  
| Top (y: 0 → −300)  
| Y  
| 600 ms (position), 300 ms (opacity, delayed 300 ms)  
|-  
| {{code|left}}  
| Right (x: 300 → 0)  
| Left (x: 0 → −300)  
| X  
| 600 ms (position), 300 ms (opacity, delayed 300 ms)  
|-  
| {{code|right}}  
| Left (x: −300 → 0)  
| Right (x: 0 → 300)  
| X  
| 600 ms (position), 300 ms (opacity, delayed 300 ms)

All eight {{code|Transition}} objects are declared as direct children of the {{code|StackView}} (not inside {{code|routeTransitions}}); {{code|routeTransitions}} holds references to them by id.  
  
=====Enter transition structure=====  
  
Every enter transition uses a {{code|ParallelAnimation}} containing:  
# A {{code|NumberAnimation}} on the position property (x or y), running for the full 600 ms with {{code|Easing.InOutQuint}}.  
# A {{code|SequentialAnimation}} containing:  
## A {{code|ScriptAction}} calling {{code|BlackMesaUtils.clearUIElementsData()}} — resets keyboard/controller navigation state immediately.  
## A {{code|PauseAnimation}} of 300 ms — waits until the position animation is halfway complete before fading in.  
## A {{code|NumberAnimation}} on {{code|opacity}} from 0.0 to 1.0 over 300 ms — fades the new view in.  
## A {{code|ScriptAction}} calling {{code|parseRouteUIItems()}} — traverses the now-visible view to register its interactive elements.  
  
=====Exit transition structure=====  
  
Every exit transition uses a {{code|ParallelAnimation}} containing:  
# A {{code|NumberAnimation}} on the position property, 600 ms, {{code|Easing.InOutQuint}}.  
# A {{code|NumberAnimation}} on {{code|opacity}} from 1.0 to 0.0 over 300 ms (no delay — the exiting view fades out immediately).

====Notable Issues====  
  
1. '''Implicit scope dependencies.''' {{code|emptyRoute}} and {{code|appRoot}} are referenced inside {{code|router.qml}} but defined in {{code|main.qml}}. This works because QML resolves identifiers through the visual parent scope, but it creates a hidden coupling: {{code|router.qml}} cannot be used outside of {{code|main.qml}} without breaking.  
  
2. '''Dead branch: <code><nowiki>route.name === Routes.empty.name</nowiki></code> on line 65.''' The condition on line 62 already catches all navigations to the empty route ({{code|route.name === Routes.empty.name}}). The same sub-condition on line 65 is therefore unreachable. The intended {{code|down}} transition for navigating to the empty route via that branch is never applied through that path (though it is applied via line 62's {{code|up}} transition, which takes precedence).  
  
3. '''{{code|isInGame}} is not reactively bound in the pushed {{code|RouteView}}.''' The value is captured at push time via {{code|properties: { isInGame: outlet.isInGame }}}. If {{code|appRoot.isInGame}} changes after the view is pushed (e.g. during a multiplayer disconnect), the active {{code|RouteView}}'s {{code|isInGame}} property will not update until the next navigation.  
  
4. '''Signal connections are never explicitly disconnected.''' After a {{code|pop}} or {{code|replace}}, the destroyed {{code|RouteView}}'s signals are cleaned up automatically by the QML engine. This is safe in practice but means there is no explicit lifecycle management for signal connections.  
  
5. '''{{code|allowSameRoute}} is never used by any caller.''' The parameter exists to allow reloading the same route, but no call site in the codebase passes it as {{code|true}}.  
  
6. '''Empty stack after {{code|pop}} is not guarded.''' After {{code|outlet.pop()}}, {{code|currentRoute}} is set from {{code|outlet.currentItem.routeName}}. If the stack is empty after the pop (which should not happen in normal flow but is not structurally prevented), {{code|outlet.currentItem}} will be {{code|null}} and the property access will throw a TypeError.  
  
7. '''{{code|actions}} is a plain JavaScript object.''' It cannot be extended or overridden from outside {{code|router.qml}} without modifying the file. Adding new action-type routes requires editing the {{code|actions}} literal directly.

===routes.qml===  
  
{{code|routes.qml}} is registered in {{code|qmldir}} as the {{code|Routes}} singleton. It is the central route registry for the entire UI — a flat list of {{code|Route}} objects, each describing one navigable destination. {{code|router.qml}} consumes this singleton exclusively via {{code|Routes[routeName]}} lookups.  
  
The file is 182 lines and contains 22 route definitions organized into six logical groups.  
  
====Route component====  
  
Each entry is an instance of {{code|Route}} (defined in {{code|route.qml}}, registered in {{code|qmldir}} as {{code|Route 1.0}}). The {{code|Route}} type is an {{code|Item}} with the following properties:  
  
{| class="standard-table"  
! Property  
! Type  
! Default  
! Purpose  
|-  
| {{code|name}}  
| {{code|string}}  
| (empty)  
| Unique identifier used as the lookup key in {{code|Routes[name]}} and stored in {{code|RouteView.routeName}}.  
|-  
| {{code|path}}  
| {{code|string}}  
| (empty)  
| Dot-separated logical path (e.g. {{code|"campaign.newgame"}}). Used by {{code|component-header.qml}} to determine which main-nav and sub-nav tabs to highlight.  
|-  
| {{code|qmlFile}}  
| {{code|string}}  
| (empty)  
| Filename of the {{code|RouteView}} QML file to load. Passed directly to {{code|StackView.push()}} or {{code|StackView.replace()}}.  
|-  
| {{code|alert}}  
| {{code|bool}}  
| {{code|false}}  
| If {{code|true}}, the route is always pushed onto the stack (never replaced) and can only be dismissed by a pop. Alert routes use the {{code|upEnterTransition}} animation.  
|-  
| {{code|action}}  
| {{code|string}}  
| (empty)  
| If set, {{code|router.qml}} executes {{code|actions[route.action]()}} instead of loading a view. No {{code|qmlFile}} is needed.  
|-  
| {{code|passthrough}}  
| {{code|bool}}  
| {{code|false}}  
| If {{code|true}}, the route is immediately resolved to {{code|Routes[route.destination]}} before any transition logic runs.  
|-  
| {{code|destination}}  
| {{code|string}}  
| (empty)  
| The {{code|name}} of the route to redirect to when {{code|passthrough}} is {{code|true}}.  
|-  
| {{code|rank}}  
| {{code|real}}  
| {{code|0.0}}  
| Numeric position in the navigation hierarchy. When transitioning between two non-special routes, the router compares ranks to choose a left or right slide animation: higher rank slides in from the right, lower rank slides in from the left.  
|}

====How routes are consumed====  
  
{{code|router.qml}} is the sole consumer of {{code|Routes}}. Its {{code|setRoute(newRouteName)}} function performs the following steps in order:  
  
# Look up the route: <code><nowiki>var route = Routes[newRouteName]</nowiki></code>.  
# Resolve passthrough: if <code><nowiki>route.passthrough</nowiki></code>, replace with <code><nowiki>Routes[route.destination]</nowiki></code>.  
# Guard same-route: return early if the resolved route name equals {{code|currentRoute.name}} (unless {{code|allowSameRoute}} is set).  
# Guard navigation intercept: call <code><nowiki>outlet.currentItem.onRouteWillChange(newRouteName)</nowiki></code> if it exists; return early if it returns {{code|true}} (used by {{code|routeview-video.qml}} to block navigation with unsaved changes).  
# Execute action: if <code><nowiki>route.action</nowiki></code> is set, call <code><nowiki>actions[route.action]()</nowiki></code> and return. The only registered action is {{code|OPEN_STEAMWORKSHOP}}, which calls <code><nowiki>BlackMesaEngine.activateSteamOverlayToWebPage(...)</nowiki></code>.  
# Determine transition: call {{code|_getRouteTransitionConfig}} to select the animation direction and stack operation ({{code|push}}, {{code|replace}}, or {{code|pop}}).  
# Execute transition: call {{code|outlet.push()}}, {{code|outlet.replace()}}, or {{code|outlet.pop()}} with the resolved {{code|qmlFile}} and properties.  
# Connect signals: connect the new {{code|RouteView}}'s {{code|routeRequest}}, {{code|loadGameRequest}}, {{code|loadMapRequest}}, and {{code|saveGameRequest}} signals to the router's handlers.  
  
====Transition direction logic====  
  
{{code|_getRouteTransitionConfig}} selects one of four named transitions based on the current and target route:  
  
{| class="standard-table"  
! Condition (evaluated in order)  
! Stack operation  
! Transition  
|-  
| No current route (initial load)  
| {{code|push}}  
| {{code|down}} (default)  
|-  
| <code><nowiki>route.name === Routes.back.name</nowiki></code>  
| {{code|pop}}  
| {{code|down}} if current route is alert; {{code|up}} otherwise  
|-  
| <code><nowiki>route.alert || route.name === Routes.empty.name</nowiki></code>  
| {{code|push}}  
| {{code|up}}  
|-  
| <code><nowiki>currentRoute.name === Routes.index.name</nowiki></code>  
| {{code|push}}  
| {{code|down}}  
|-  
| (all other cases)  
| {{code|replace}}  
| {{code|right}} if <code><nowiki>currentRoute.rank > route.rank</nowiki></code>; {{code|left}} otherwise  
|}  
  
Each named transition is a {{code|ParallelAnimation}} combining a positional slide ({{code|x}} or {{code|y}}, ±300px, 600ms, {{code|Easing.InOutQuint}}) with an opacity fade (0→1 or 1→0, 300ms). Enter transitions also fire two {{code|ScriptAction}} steps: {{code|BlackMesaUtils.clearUIElementsData()}} at the start and {{code|parseRouteUIItems()}} (which calls {{code|BlackMesaUtils.traverseUIElements()}} and {{code|BlackMesaUtils.afterTraverseCallback()}}) after the 300ms pause, so the navigation system is rebuilt for the new view once it is visible.  
  
====Notable Issues====  
  
1. '''{{code|rank}} on passthrough routes is never used.''' Passthrough routes are resolved to their destination before {{code|_getRouteTransitionConfig}} is called. The {{code|rank}} values on {{code|campaign}} (1.0), {{code|multiplayer}} (2.0), {{code|options}} (3.0), and {{code|steamworkshop}} (5.0) are therefore dead data.  
  
2. '''Dead branch for <code><nowiki>route.name === Routes.empty.name</nowiki></code>.''' The condition appears twice in {{code|_getRouteTransitionConfig}}: once on line 62 (combined with the alert check, always matched first) and once on line 65 (unreachable). The intended {{code|down}} transition for navigating to the empty route via the second branch is never applied.  
  
3. '''{{code|Routes}} is an {{code|Item}}, not a {{code|QtObject}}.''' The root element is {{code|Item}} rather than {{code|QtObject}}. Since {{code|Route}} extends {{code|Item}} (it uses {{code|anchors.fill: parent}}), each of the 22 {{code|Route}} children is a full visual item parented to the {{code|Routes}} singleton, which is itself parented to the QML engine's root. This is unnecessary overhead; {{code|QtObject}} children would suffice for a pure data registry.  
  
4. '''{{code|browse}} has no {{code|path}}.''' The {{code|path}} property is used by {{code|component-header.qml}} to determine which tab to highlight. Since {{code|browse}} has no {{code|path}}, navigating to it (which opens the Steam overlay without changing the active view) leaves the header in whatever state it was in before, which is the correct visual behaviour but is implicit rather than explicit.  
  
5. '''No route for {{code|routeview-campaigns.qml}}.''' The file exists in the UI directory but has no corresponding entry in {{code|routes.qml}} and is unreachable through any normal navigation flow.

===routeview.qml===  
  
{{code|routeview.qml}} is the '''base class''' for every page in the Black Mesa menu system. It is registered in {{code|qmldir}} as the {{code|RouteView}} component (version 1.0) and is used as the root element of all 19 {{code|routeview-*.qml}} files.  
  
The file is 28 lines. It defines no visual content of its own — it is a pure structural contract: a {{code|FocusScope}} that fills its parent, declares four signals, and exposes two properties that the router populates on every push.  
  
====Base Type====  
  
{{code|RouteView}} extends {{code|FocusScope}} (from {{code|QtQuick 2.9}}), not {{code|Item}}. This means:  
  
* Keyboard focus is scoped to the view. When a {{code|RouteView}} has active focus, {{code|Keys}} handlers inside it receive events before the parent.  
* {{code|activeFocus}} propagates inward to the first focusable child, which is the mechanism that allows {{code|main.qml}}'s {{code|Keys.onPressed}} to delegate to {{code|BlackMesaUtils.navigationUIHandle(event)}}.  
  
The root element fills its parent on all four sides and also explicitly sets {{code|width}} and {{code|height}} to {{code|parent.width}} and {{code|parent.height}}, making the fill redundant but harmless.

====onRouteWillChange Hook====  
  
{{code|routeview.qml}} does '''not''' declare an {{code|onRouteWillChange}} function. However, {{code|router.qml}} checks for it dynamically before every navigation:  
  
<syntaxhighlight lang="qml">  
if (outlet.currentItem && typeof outlet.currentItem.onRouteWillChange === 'function') {  
    if (outlet.currentItem.onRouteWillChange(newRouteName)) {  
        return; // navigation intercepted  
    }  
}  
</syntaxhighlight>  
  
If the function exists on the current view and returns a truthy value, the navigation is cancelled. Only {{code|routeview-video.qml}} implements this hook, using it to show an unsaved-changes confirmation dialog when the user tries to navigate away with pending video settings.

====Notable Issues====  
  
1. '''Signal connections are never explicitly disconnected.''' After a {{code|pop}}, the destroyed {{code|RouteView}} instance's signals are disconnected automatically by the QML engine. However, after a {{code|replace}}, the replaced item is also destroyed, so the same automatic cleanup applies. The comment in {{code|router.qml}} acknowledges this implicitly. In practice this is safe, but it means there is no explicit lifecycle management for signal connections.  
  
2. '''{{code|opacity: 0}} is set on the base class, not in the transition.''' If a {{code|RouteView}} is ever instantiated outside of {{code|router.qml}}'s transition system (e.g. directly in a {{code|Loader}}), it will be permanently invisible unless {{code|opacity}} is explicitly overridden, since no transition will run to animate it to {{code|1}}.  
  
3. '''{{code|routeName}} is a writable string, not a reference to a {{code|Route}} object.''' The router stores only the name string, not the full {{code|Route}} object. After a {{code|pop}}, the router must look up the route by name via <code><nowiki>Routes[outlet.currentItem.routeName]</nowiki></code>. If {{code|routeName}} is ever set to a value that does not correspond to a key in {{code|Routes}}, {{code|currentRoute}} will be set to {{code|undefined}}, breaking all subsequent transition logic.

====Notable Issues====  
  
1. '''{{code|blurred}} state is unreachable.''' The delegate's {{code|MouseArea}} has no {{code|onEntered}}, {{code|onExited}}, or {{code|onClicked}} handler that transitions to {{code|blurred}}. The initial state is set directly to either {{code|focused}} or {{code|locked}} and never changes. The {{code|blurred}} state (white text, no background border) is defined but dead code.  
  
2. '''No keyboard or controller navigation.''' No element has an {{code|objectName}} matching the patterns used by {{code|BlackMesaUtils.traverseUIElements()}} ({{code|ui:tab}}, {{code|ui:btn:*}}, {{code|ui:option-item}}). The page cannot be navigated with a keyboard or controller beyond scrolling via the {{code|GridView}}'s built-in flick behavior, and even that requires mouse/touch since there are no {{code|Keys}} handlers.  
  
3. '''Synthetic hidden card uses wrong field name.''' The synthetic card sets {{code|image: ""}} but the delegate reads {{code|thumbnailPath}}. The {{code|thumbnailPath}} role is absent from the synthetic card's object, so {{code|achievementThumbnailImage.source}} will be {{code|undefined}}, causing a silent image load failure.  

4. '''{{code|pageHeight}} mixes {{code|widthScale}} and {{code|heightScale}}.''' The formula is <code><nowiki>cellH * Math.floor(Math.ceil(750 * Theme.heightScale) / cellH)</nowiki></code>. {{code|cellH}} uses {{code|Theme.widthScale}} while the dividend uses {{code|Theme.heightScale}}. At non-square aspect ratios the snapping calculation produces an inconsistent result.  
  
5. '''{{code|headerHeight}}, {{code|cellW}}, and {{code|cellH}} all use {{code|Theme.widthScale}}.''' None of these use {{code|Theme.heightScale}}, so the header strip and all cells scale uniformly with screen width. At non-standard aspect ratios, cells will be taller or shorter than intended relative to the screen height.  
  
6. '''{{code|total}} counts hidden achievements; the grid does not.''' The {{code|total}} property (used in the header progress bar denominator and in the {{code|headerFraction}} text) is set to {{code|achievements.length}}, which includes hidden-and-incomplete achievements. However, those achievements are not appended to the model — they are replaced by a single synthetic card. The header therefore correctly shows the true total, but the number of visible cards is less than {{code|total}}, which may confuse players who count the cards.  
  
7. '''{{code|achievementDescription}} uses explicit {{code|width}} instead of {{code|anchors.right}}.''' The width is set to <code><nowiki>parent.width - anchors.leftMargin * 2</nowiki></code>, which subtracts the left margin twice. Since there is no right margin applied, the text can overflow the right edge of the center zone by {{code|anchors.leftMargin}} pixels.  
  
8. '''{{code|VerticalScrollBar}} is always visible.''' {{code|visible: true}} is hardcoded. The scrollbar is shown even when all achievements fit within {{code|pageHeight}}, which is uncommon but possible for games with very few achievements.  
  
9. '''All strings bypass {{code|L10n}}.''' Every localized string in the file uses {{code|BlackMesaEngine.getLocalizedString()}} directly with {{code|#BlackMesaUI_*}} keys, inconsistent with all other route views which use the {{code|L10n}} singleton. The only {{code|L10n}} reference to achievements is {{code|L10n.strings.menus.achievements}}, used in {{code|component-header.qml}} for the main nav tab label.  
  
10. '''No {{code|id}} on the root {{code|RouteView}}.''' Child elements cannot reference the root by id. The {{code|total}} and {{code|completed}} properties on the root are accessed from the {{code|ListModel}}'s {{code|Component.onCompleted}} via implicit scope, which works but is fragile.

====Notable Issues====  
  
1. '''Root {{code|id}} is {{code|newGame}}.''' The root {{code|RouteView}} uses {{code|id: newGame}}, identical to {{code|routeview-newgame.qml}}. This is a copy-paste artifact. 2. 7. '''{{code|showLeft [[=]] false}} is hardcoded on phase transition.''' When switching to chapter view, {{code|showLeft}} is always forced to {{code|false}} regardless of the chapter count. This is correct for the initial display (the carousel always starts at the leftmost position), but it means the left arrow is never shown even if the user had previously scrolled right and then triggered a re-population — though in practice this scenario cannot occur since {{code|levels.clear()}} resets the carousel position.

The music volume is only applied from {{command|snd_musicvolume}} when {{code|startAmbient()}} is next called. Live music volume adjustment while the menu is open does not work.  
  
2. '''{{code|rtlLanguages.indexOf(value) == 0}} checks position, not membership.''' {{code|Array.indexOf}} returns the index of the element, or {{code|-1}} if not found. Comparing to {{code|0}} means the condition is only {{code|true}} when {{code|value}} is the '''first''' element of the array ({{code|"arabic"}}). All other RTL languages in the list — aramaic, azeri, dhivehi, maldivian, hebrew, kurdish, sorani, persian, farsi, urdu — will never set {{command|cc_rightaligned}} to 1. The correct check is <code><nowiki>rtlLanguages.indexOf(value) !== -1</nowiki></code>.  
  
3. '''{{code|audio_captioningLang}} declares {{code|valueType: "int"}} but stores strings.''' The option values are language name strings (e.g. {{code|"arabic"}}, {{code|"english"}}). The {{code|valueType}} should be {{code|"string"}}. Since this item uses a complex getter/setter and has no {{code|cvar}} field, the {{code|valueType}} is likely ignored by the {{code|OptionsList}} at runtime, making this a documentation/consistency issue rather than a functional bug.  
  
4. '''{{code|audio_captioning}} declares {{code|valueType: "int"}} but the complex getter returns strings.''' The getter returns {{code|"0"}}, {{code|"1"}}, or {{code|"2"}} as string values. As with {{code|audio_captioningLang}}, the {{code|valueType}} is irrelevant for complex-getter items, but the declaration is misleading.  
  
5. '''Trailing comma in {{code|audio_captioningLang}} options array.''' The last entry ({{code|"vietnamese"}}) is followed by a trailing comma. This is valid in ES5+ JavaScript but is inconsistent with all other option arrays in the file.  
  
6. '''{{code|disabled: false}} is explicitly set on {{code|audio_captioningLang}}.''' All other items rely on the default. This is redundant but harmless; the actual disabled state is managed dynamically by {{code|setLanguageState()}}.  
  
7. '''{{code|audio_captioning}} setter assigns {{code|subs = 1}} for the "off" case.''' When value is {{code|"0"}} (no captions), the setter writes {{command|cc_subtitles}} as {{code|1}}. This is a latent inconsistency: if {{command|closecaption}} is later set to 1 externally (e.g. via console), subtitles would be active even though the user selected "No Captions". The getter correctly handles this by checking {{command|closecaption}} first, so the UI will still display "No Captions" correctly, but the underlying CVar state is untidy.

====Notable Issues====  
1. '''{{code|total}} is a dead property.''' It is declared as {{code|property int total}} but is never assigned or read anywhere in the file.  

2. '''Dead engine call in the timer.''' <code><nowiki>var listSaveEntries = BlackMesaEngine.listSaveEntries()</nowiki></code> is called inside {{code|deferredCompletedTimer.onTriggered}} and the result is immediately discarded. This makes an unnecessary engine call on every page load.

4. '''{{code|type: "join"}} has no effect.''' {{code|BlackMesaUtils.traverseUIElements()}} classifies items with {{code|objectName: "ui:option-item"}} as option items regardless of their {{code|type}} property. The {{code|type: "join"}} value is unique to this file and is not handled by any navigation logic.  

5. '''No single-click handler.''' The delegate only handles {{code|onDoubleClicked}} for connecting. Single-click focuses the row visually. The {{code|callback}} property provides the Enter-key connect action via the navigation system, but there is no explicit {{code|onClicked}} handler, making mouse single-click a no-op.

====Notable Issues====  
1. '''Broken padding syntax.''' The delegate sets {{code|padding}} using a JavaScript block expression:  
<syntaxhighlight lang="qml">padding: {  
    left: Math.ceil(16 * Theme.widthScale);  
    top: Math.ceil(16 * Theme.heightScale);

    right: Math.ceil(24 * Theme.widthScale);

2. In QML, this is not a property group assignment — it is a JavaScript block with labeled statements. The value of the block is the last expression, so {{code|padding}} (all four sides) is set to <code><nowiki>Math.ceil(24 * Theme.widthScale)</nowiki></code>. 5. '''Hardcoded, non-localized content.''' The entire privacy policy is embedded as a string literal in the QML source. It is English-only, not routed through the {{code|L10n}} singleton or the engine localization system, and cannot be updated without a code change.  

6. '''Single-item {{code|ListView}}.''' Using a {{code|ListView}} with a one-item {{code|ListModel}} to render a single {{code|Text}} element is unnecessarily complex. A plain {{code|Flickable}} or {{code|ScrollView}} wrapping a {{code|Text}} directly would be simpler and more idiomatic.

====saveGameRequest Signal Chain====  
  
Passing {{code|null}} to {{code|saveGameRequest}} triggers the following chain:  
  
# {{code|saveBeforeQuitView.saveGameRequest(null)}} fires the signal defined in the {{code|RouteView}} base class ({{code|routeview.qml}}).  
# {{code|router.qml}} has connected this signal to {{code|_saveGameRequestHandler}}, which re-emits {{code|outlet.saveGameRequest(filename)}}.  
# The upstream handler (in {{code|main.qml}}) calls {{code|BlackMesaUtils.saveGame(null, callback)}}.  
# {{code|BlackMesaUtils.saveGame}} auto-generates a zero-padded filename in the format <code><nowiki>bms-NNN</nowiki></code> (e.g. {{code|bms-001}}) and issues the engine command <code><nowiki>gameui_hide;save bms-NNN</nowiki></code>.  
# The quit command then executes immediately after, without waiting for the save to complete.  
  
The lack of any callback or deferred execution between the save and quit calls means the game quits synchronously after issuing the save command, relying on the engine to flush the save before exiting.

=====Row 2 — GridView (grid_view)=====
The scrollable grid of cards. Key properties:
* '''cellWidth''': {{code|max(cellW, grid_view.width / 5) - 16 * Theme.widthScale}} — tries to fit 5 columns but never goes below cellW (360px scaled); subtracts 16px for the scrollbar.
* '''cellHeight''': {{code|cellH}} (220px scaled).
* '''clip: true''', {{code|keyNavigationEnabled: true}}.
* '''model'''}: '''translators_proofreaders''' when {{code|activeTab === 0}}, else '''translators_credits'''.
* '''delegate''': '''proofreaderDelegate''' when {{code|activeTab === 0}}, else '''translatorDelegate'''.
* '''ScrollBar.vertical''': '''VerticalScrollBar''' (always visible).
* '''Component.onCompleted''': calls {{code|grid_view.forceActiveFocus()}} so keyboard navigation works immediately on page load.

====Keyboard scrolling quirk====
'''Keys.onUpPressed''' and '''Keys.onDownPressed''' call {{code|scrollBar.decrease()}}/{{code|scrollBar.increase()}} directly on the scrollbar, rather than letting '''keyNavigationEnabled''' move between grid cells. This means Up/Down scroll the list rather than moving the selection row by row.

====Notable Issues====
1. '''itemsToShowOnRow''' references '''proofreadersContainer.width''', which does not exist anywhere in the file. This property will always be NaN/undefined at runtime, though it is never used in the layout either.

2. '''pageWidth''', '''headerHeight''', '''headerOffset''', '''footerOffset''' are all defined but never referenced in the layout — dead properties.

3. Tab labels use {{code|BlackMesaEngine.getLocalizedString()}} directly instead of the '''L10n''' singleton used everywhere else in the UI.

4. All card text uses '''Theme.colors.highlight''' (orange) for every field — including secondary info like Discord name and word count — rather than using '''Theme.colors.text''' or '''Theme.colors.dimmedText''' for secondary fields as other components do.

===routeview-video.qml===
This is the Video Options settings page. It is a '''RouteView''' (id: '''videoOptionsView''') containing a single '''OptionsList''', a footer description panel, a warning header, and a confirmation alert.

====Top-level Properties====
*'''blockingRouteName''' - stores the destination route when navigation is intercepted due to unsaved changes.
*'''costFontSize''' - scaled font size ({{code|16 * Theme.widthScale}}) for the footer description panel.
*'''headerWarningVisibility''' - boolean that shows/hides the warning icon in the top-right corner.
*'''advancedQualityKeys''' - array of 17 setting keys that are controlled by the overall quality preset.

====Navigation Guard====
{{code|onRouteWillChange(newRouteName)}} intercepts any attempt to leave the page. If '''videoOptions.hasPendingChanges''' is true, it stores the destination in '''blockingRouteName''', shows '''confirmAlert''', and returns true to block the navigation.

====OptionsList — videoOptions====
The main content area. It uses {{code|batchUpdates: true}} and shows 8 visible rows at a time.

=====Quality Preset System=====
{{code|Component.onCompleted}} defines a '''qualitySettings''' object with 5 presets (keys "0"–"4"): '''Potato''', '''Low''', '''Medium''', '''High''', '''Ultra'''. Each preset is a map of all 17 '''advancedQualityKeys''' to their target values.

'''onSettingsReset'''' reads [[mat_easymenu_quality_level]] and calls {{code|setAdvancedSettingsState()}} to restore the preset.

'''onRequestSettingsChange''' handles two cases, after every change it calls {{code|updateHeaderWarningVisibility()}}:
*If the changed key is '''video_quality''', it applies the matching preset via {{code|setAdvancedSettingsState()}}.
*If the changed key is one of the 17 advanced keys, it sets '''video_quality''' to "5" ('''Custom''').

{{code|setAdvancedSettingsState(settings)}} iterates '''advancedQualityKeys''' and calls {{code|setValue()}} for each key, but only if the current quality is not already '''Custom''' ("5").

{{code|updateHeaderWarningVisibility()}} scans all select-type model items and counts how many currently-selected options have warning: 1. Sets '''headerWarningVisibility''' accordingly.

====groups — Grouped Apply Callbacks====
A single function {{code|displayMode()}} handles both '''video_resolution''' and '''video_displayMode''' together. It parses the resolution string, immediately updates '''appRoot.width'''/'''height''' and '''Theme.widthScale'''/'''heightScale''' so the UI rescales at once, sets {{code|reloadPageAfterApplyChanges [[=]] true}}, then issues [[mat_setvideomode]] with the correct windowed/borderless flags.

====setComplex — Multi-CVar Setters====
Settings that map to more than one engine CVar have a named function here instead of a simple cvar property:
*'''video_filtering''' - [[mat_trilinear]], [[mat_forceaniso]].
*'''video_waterDetail''' - [[r_waterforceexpensive]], [[r_waterforcereflectentities]].
*'''video_dynamicShadowQuality''' - [[nr_shadow_active]], [[nr_shadow_quality]], [[nr_shadow_max_passes_per_frame]].
*'''video_dynamicShadowMemory''' - [[nr_shadow_res]].
*'''video_dynamicShadowSoftness''' - [[nr_shadow_filter_quality]].
*'''video_dynamicLightsQuality''' - [[nr_lights_quality]], [[r_4way_minimal_mode]], [[r_4way_use_fast_normals]] (with override support).
*'''video_godRays''' - [[np_gr_quality]], [[np_gr_quality_sample_count]], [[np_gr_quality_pass_count]].
*'''video_csmQuality''' - [[cl_csm_enabled]], [[cl_csm_qualitymode]].
*'''video_csmMemory''' - [[cl_csm_memoryusage]].
*'''video_unlockHighendUnsupported''' - [[mat_unlock_gfx_highend_unsupported]]; also sets {{code|reloadPageAfterApplyChanges [[=]] true}}.

Several setters enforce caps when [[mat_unlock_gfx_highend_unsupported]] is false (e.g. dynamic shadow quality capped at 4, CSM quality capped at 3, dynamic lights capped at 4).

====getComplex — Multi-CVar Getters====
Mirror functions that read the same console variables and reconstruct the UI value. They also silently clamp out-of-range values back to valid ones (the comment calls this "terrible and hacky" but intentional — it self-heals console-edited values).

{{note|'''video_resolution''' reads from '''Theme.rootWidth''' and '''Theme.rootHeight''' rather than from an engine console variable.}}
{{bug|hidetested=1|{{code|getComplex.video_godRays()}} has an unreachable return "0" at line 591 after the else branch already returns.}}

====ListModel — The 25 Settings Items====
Built dynamically in '''Component.onCompleted'''. Some of the components has {{code|warning: 1}}, contributes to '''headerWarningVisibility'''.
{{note|A '''Potato''' quality tier and '''video_unlockPotato''' checkbox are fully implemented in the code but entirely commented out. '''unlockedPotato''' is hardcoded to true in all getters/setters, meaning '''Potato'''-tier options are silently available in the advanced settings dropdowns but the preset and unlock checkbox are disabled.}}

====Footer Description Panel — footerGraphicDescription====
An Item anchored to the bottom-left of the page (leaving 600px on the right for the options list scrollbar area). It contains 7 text elements:
*'''footerGraphicDescriptionText_desc''' — the setting's '''description_main''' string (wraps to a calculated width).
*'''footerGraphicDescriptionText_cost_CPU'''/'''GPU'''/'''RAM''' — labels "CPU:", "GPU:", "RAM:" (white, only shown if the setting has a cost).
*'''footerGraphicDescriptionText_cost_CPU'''/'''GPU'''/'''RAM_value''' — the cost values, colored dynamically.

{{code|onSelectionChanged(modelSelected)}} populates all 7 texts and applies a color map to the value texts:
*Major - #FF4D2D (red).
*Moderate - #FFD53E (yellow).
*Minor - #55E835 (green).
*None - white.
*(empty) - #000000 (black/hidden).

====Warning Header — warningHeaderSign/warningHeaderText====
A warning icon ('''ui/images/warning.png''') and text label anchored to the top-right of the page. Both are {{code|visible: headerWarningVisibility}}. They appear whenever any currently-selected option has {{code|warning: 1}} (i.e. Water High, CSM Insane, Dynamic Lights Ultra/Insane).

====Confirmation Alert — confirmAlert====
An Alert dialog shown when the user tries to navigate away with unsaved changes. It has three buttons:
*Apply ('''CTAButton''') — calls {{code|videoOptions.flushPendingChanges()}} then navigates to '''blockingRouteName'''.
*Discard ('''WarningButton''') — navigates to blockingRouteName without saving.
*Cancel ('''DefaultButton''') — clears blockingRouteName and hides the alert.
